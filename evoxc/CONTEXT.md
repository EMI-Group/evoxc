# evoxc package — public API contract

## Intent

The `evoxc` package — **EvoX Compiler**: a minimal, explicit, compiler-neutral tensor graph compiler and runtime.
See root `../CONTEXT.md` for the binding principles, the four-concept value-model table, the import-acyclicity contract, the error strategy, and the non-goals — all binding here.
This file owns the **public API surface** (names that must exist) and the **cross-module contracts** every submodule must honor; per-feature implementation detail lives in the child nodes listed in the routing table.
This file must stay under the ~64 KB per-file read limit — push new detail down to the owning child node instead of growing it.

Pipeline objects are distinct public types (`Defn` → `Graph` → `LoweredProgram` → `CompiledArtifact` → `Executable` → `Tensor`); no function silently consumes an earlier-stage object and performs the missing steps.

## Public API surface (the contract — must exist, exact names)

**Staging & pipeline** (owned by `pipeline.py`):
- `@evoxc.defn` → `Defn` (calling a `Defn` with concrete tensors must raise `TraceError` directing to `trace`/`evaluate`)
- `evoxc.trace(fn_or_defn, *specs) -> Graph` (accepts nested structures of `TensorSpec` + static values)
- `evoxc.lower(graph, backend=None, **options) -> LoweredProgram`; `evoxc.compile(lowered, backend=None, **options) -> CompiledArtifact`; `evoxc.load(artifact, backend=None, device=None) -> Executable`
- `evoxc.run(executable, *args) -> outputs` (structured inputs/outputs via TreeSpec; validates static fields)
- `evoxc.bind(obj, **bindings) -> BoundExecutable|callable` (pure argument-supply sugar; validates names/dtypes/shapes/devices; never alters the graph)
- `evoxc.build(fn, *specs, backend=None, device=None, **options) -> Executable` — documented shorthand for trace→lower→compile→load
- `evoxc.evaluate(fn, *args, backend=None, device=None, **options)` — documented shorthand: derive specs → build → run (deriving a spec from a concrete tensor snapshots shape+dtype only)
- `evoxc.build_cached(fn, *specs, backend=None, device=None, cache=None, **options) -> Executable` — documented shorthand for a MEMOIZED `build` (see "Memoized build sugar" below)
- `evoxc.CompileCache` — the in-memory LRU compile cache backing `build_cached` (default `maxsize=128`)
- `Executable.synchronize()` — wait until all device work submitted by previous `run()` calls on this executable has completed; the output Tensors' values are already valid before the call (any read awaits), only their *timing* needs this. It is an EXPLICIT caller-invoked primitive — nothing in evoxc calls it implicitly and `evoxc.run` is unchanged (no per-call sync; dispatch overlap stays a feature); a backend whose `run()` already blocks (numpy, iree) needs no work here, so the method is a documented no-op on them. `BoundExecutable.synchronize()` delegates, so `evoxc.bind(...)` results expose the same call shape.
- **`build`/`evaluate`/`build_cached` env defaults** (explicit kwargs ALWAYS win; env read lazily at call time): unset `backend` from `EVOXC_BACKEND` (default `"numpy"` when unset/empty); unset `device` from `EVOXC_DEVICE` (`"kind[:index]"`, e.g. `"cpu"`/`"cuda:0"`/`"rocm:0"`/`"vulkan:0"`, parsed to `core.Device`; malformed → `DeviceError` naming the variable and value); unset `target_backends` from `EVOXC_TARGET_BACKENDS` (comma-separated), otherwise an iree-family backend (name startswith `"iree"`) infers it from the resolved device (`cuda` → `["cuda"]`, `rocm`/`hip` → `["rocm"]`, `vulkan` → `["vulkan-spirv"]`, `cpu` → `["llvm-cpu"]`). AMD ROCm devices are spelled `"rocm"` (canonical) or the accepted alias `"hip"` — both valid and equivalent, never rewritten. The explicit stage functions (`lower`/`compile`/`load`) keep their documented defaults. Implementation: `pipeline._resolve_backend_device`; regression suite `tests/pipeline_env_defaults_test.py`.
- `evoxc.io` — namespaced submodule (like `evoxc.random`, NOT flat top-level names): `evoxc.io.prefetch(host_tensor, device) -> AsyncCopy`, `evoxc.io.sink(device_tensor) -> AsyncCopy`, `evoxc.io.wait_all(timeout=None)`, class `evoxc.io.AsyncCopy` (see "evoxc.io" below)

## Inspection (pure reads)

Every pipeline object exposes a `__repr__` and read-only helpers; none of them traces, compiles, executes, transfers or mutates anything, and every dict-returning helper is JSON-safe.
- `Graph` (owned by `./trace/`): `repr` carries op / function / tensor-input / static-value / output counts plus a `batch report` marker; `summary() -> dict` with keys `functions`, `op_count` (all nesting levels), `op_counts_by_category`, `tensor_inputs`/`tensor_outputs` (`{"path","shape","dtype"}`), `static_values` (`{"path","kind","value_repr"}`), `source_location_count`, `has_batch_report`, `digest`; `digest() -> str` = sha256 over the canonical serialized module + signature (process-stable for the same source; excludes `source_locations` and `batch_report`); `text() -> str` = the pretty-printed IR that `print()` writes.
- `LoweredProgram` / `CompiledArtifact` (owned by `./backends/program.py`): `repr` carries backend, target, payload kind + size and leaf counts; `summary() -> dict` with keys `backend`, `target`, `payload_kind`, `payload_bytes`, `input_count`/`output_count`, `input_shapes`/`output_shapes`, `input_dtypes`, `static_value_count`, `required_custom_ops`, `runtime_dependencies`; `source_text() -> str | None` returns the human-readable program text (MLIR/StableHLO text or the serialized-IR pretty print) and `None` when the payload has no text form, where `text()` keeps raising; `save`/`load` are the explicit `./persist` container round trip and never compile.
- `Executable` / `BoundExecutable` (owned by `./pipeline.py`): `repr`; `summary() -> dict` with keys `backend`, `device`, `functions`, `input_count`/`output_count`, `input_specs`/`output_specs`, `input_tree`/`output_tree`, `static_value_count`, `required_ops`, `capabilities` (the registered backend's flags; `dtypes` reported as `dtype_count`), and `BoundExecutable` adds `bound_count` and reports the reduced unbound inputs; `plan_text() -> str | None` delegates to the backend executable's own textual plan (the numpy interpreter plan) and is `None` for a backend without one.
- `Defn` (owned by `./trace/defn.py`): `repr` names the wrapped function's qualname and `__module__`.
- `Tensor` (owned by `./core/tensor.py`): `repr` shows shape/dtype/device plus a compact value preview ONLY for an ndarray-backed tensor of at most 8 bool/integer/float/complex elements, and the payload class name for a device payload — it never calls `.numpy()`, never materializes a payload host copy, never forces a transfer and never raises.

## Backend options override (binding)

Design principle: *"we only took care of the graph, provide a clean pipeline, and everything else should be hack-able"* — evoxc never hardcodes compiler flags users cannot override.
- **Every stage accepts options**: `lower(graph, backend=..., **options)`, `compile(lowered, backend=..., **options)`, `load(artifact, backend=..., device=..., **options)`, `run(executable, *args, **options)`, and `build`/`evaluate`/`build_cached` forward the same options to `lower`, `compile` and `load` (a load-stage option such as the xla `plugin_path` reaches `load` through every one of them). Option keys are ADDITIVE (existing signatures keep working).
- **Option keys are validated by the framework; option values are the consumer's job.** Each backend/executable declares `KNOWN_OPTIONS: dict[stage, frozenset[str]]` (`lower`/`compile`/`load`/`run`); `evoxc.backends.options.validate_options` validates a caller's dict against the UNION of all stage sets — a key valid for ANY stage passes and is accepted-and-ignored at the others (so one dict can be forwarded), a key valid for NO stage raises `core.BackendError` listing the per-stage known sets. Flag/option VALUES otherwise pass through to the compiler (or, for exporter options, to the stablehlo Writer) — evoxc never parses compiler flags.
- **The only values evoxc itself validates** (`normalize_opt_level` / `normalize_bool_option` in `evoxc/backends/options.py`): `opt_level` (below), and BOOL-valued options — TYPE-COERCED to a real `bool` (real bools, ints 0/1, and `"1"/"0"/"true"/"false"/"yes"/"no"/"on"/"off"` case-insensitively; anything else → loud `BackendError` naming the option, value and accepted forms), so an env-style string like `"0"` can never hit the `bool("0") is True` trap.
- **Precedence (binding): explicit kwarg > env var > evoxc default.** Env vars are read lazily per call; empty/whitespace = unset; malformed → `core.BackendError` naming the variable and value. Env vars are stage-scoped; full table + parsers in `evoxc/pipeline_options.py`:

| Env var | Backend / stage | Option key | Value format |
|---|---|---|---|
| `EVOXC_IREE_COMPILE_ARGS` | iree / compile | `iree_compile_args` | shlex-split flag list (quoting IS processed, ≥1 flag) |
| `EVOXC_IREE_RUNTIME_ARGS` | iree / load | `iree_runtime_args` | shlex-split flag list |
| `EVOXC_IREE_VULKAN_TARGET` | iree / compile | `vulkan_target` | SPIR-V target profile string (`rdna3`, `sm_80`, `adreno`, …; whitespace-stripped — the VALUE is the compiler's to validate) |
| `EVOXC_XLA_COMPILE_OPTIONS` | xla / compile | `xla_compile_options` | base64 of serialized `xla.CompileOptionsProto` bytes |
| `EVOXC_TVM_TARGET` | tvm / compile | `tvm_target` | plain string (whitespace-stripped) |
| `EVOXC_TVM_PASS_CONFIGS` | tvm / compile | `tvm_pass_configs` | JSON object (must decode to a dict) |
| `EVOXC_OPT_LEVEL` | iree/tvm/xla / compile | `opt_level` | `'O0'`–`'O3'` (case-insensitive), `'0'`–`'3'`, or ints 0–3 (evoxc-validated value) |
| `EVOXC_DISPATCH_FORMATION` | iree / compile | `dispatch_formation` | `"default"`/unset = no derived flag; `"aggressive"` (case-insensitive, whitespace-stripped — the VALUE is validated by the iree adapter) = the derived `--iree-dispatch-creation-enable-aggressive-fusion` |
| `EVOXC_EIGH_ALGORITHM` | iree/tvm/xla / lower | `eigh_algorithm` | `"jacobi"` or `"jacobi_batched"` (whitespace-stripped; VALUE validated by the Writer) |
| `EVOXC_SPLIT_REDUCTION` | iree/tvm/xla / lower | `split_reduction` | bool spellings (coerced by `normalize_bool_option`) |

- **Backend-agnostic spellings.** An option every compiler adapter accepts IDENTICALLY gets ONE `EVOXC_<OPTION>` spelling rather than one variable per backend (`EVOXC_OPT_LEVEL`, `EVOXC_EIGH_ALGORITHM`, `EVOXC_SPLIT_REDUCTION`); such a row is repeated under each adapter's `(backend, stage)` key, so `lower` carries env rows like `compile`/`load` do.
- **`opt_level` — the first-class evoxc-defined compile-stage option.** Values `'O0'`–`'O3'` (case-insensitive), `'0'`–`'3'`, or ints 0–3, normalized to 0..3 by `evoxc.backends.options.normalize_opt_level`; a bad value raises a loud `core.BackendError` naming the option and accepted forms (raw compiler flags remain pass-through). Per-adapter translation: iree derives `--iree-opt-level=N`; xla sets the `CompileOptionsProto` optimization-level field; tvm sets its build optimization level; numpy documents-ignores it. Conflict rule (binding): an explicit raw flag with the same underlying name (e.g. `--iree-opt-level=N` in `iree_compile_args`, or an already-set field in `xla_compile_options`) WINS over the derived value — never both. `evoxc.bench` defaults compiler backends to `opt_level="O3"` (env-aware, explicit wins, numpy unaffected).
- **`vulkan_target` — the SPIR-V target-profile compile-stage option.** A non-empty string deriving the iree-compile default flag `--iree-vulkan-target=<profile>`, joined into the SAME defaults list as `opt_level` so the identical conflict rule applies (a raw `--iree-vulkan-target=<p>` in `iree_compile_args` WINS — never both). UNSET derives NO flag (byte-identical existing behaviour for every target); a non-str/empty value, or a value supplied without `vulkan-spirv` in `target_backends`, raises a loud `core.BackendError`. The value itself is the compiler's to validate — evoxc never parses compiler flag values. Purpose: without a profile, `vulkan-spirv` codegen uses IREE's default `vp_android_baseline_2022` (16384-byte workgroup memory, 128 threads), which cannot compile 124M-parameter-class graphs. Env `EVOXC_IREE_VULKAN_TARGET`.
- **Reserved lower-stage exporter options** (`rng_bit_generator`, `eigh_algorithm`, `split_reduction`, `sort_emission`, `while_init_rewrite`, `dot_precision` forwarded by `CompilerBackend._exporter_options` to `evoxc.backends.stablehlo` and declared in `KNOWN_OPTIONS["lower"]`; `eigh_early_exit`, `split_reduction_threshold`, `split_reduction_non_exact` are `stablehlo.export`-ONLY sub-knobs passed directly to `stablehlo.export(graph, options=...)`) — keys validated by the framework, values by the Writer with a loud `BackendError`; defaults and per-adapter sets are owned by `./backends/stablehlo/CONTEXT.md` and `./backends/adapters/CONTEXT.md`.
- **Backend defaults are minimal, documented, and OVERRIDABLE** — a user flag with the same NAME as an evoxc default drops the default (never both). iree keeps exactly `--iree-input-demote-f64-to-f32=false` (always) and `--iree-llvmcpu-target-cpu=generic` + `--iree-llvmcpu-link-embedded=false` (llvm-cpu only), and forces no process-global runtime flag (iree's own stream-ordered `--cuda_async_allocations=true` default stands; any loader/HAL flag is overridable per load via `iree_runtime_args` or `IREE_PY_RUNTIME_FLAGS`); a small DENY list is rejected with actionable reasons — `--iree-hal-target-backends` (use `target_backends`), `--iree-input-type` (StableHLO is always the input), `--iree-vm-bytecode-module-output-format` (the adapter requires the default VM flatbuffer output). The numpy reference backend documents-ignores unknown options. Per-adapter details: `./backends/adapters/CONTEXT.md`; framework contract: `./backends/CONTEXT.md`.

## Device kinds (binding)

Accepted `core.Device` kinds: `"cpu"` (always available, host memory), `"cuda"`, `"rocm"` (canonical AMD spelling; `"hip"` is an accepted equivalent alias, preserved as spelled), and `"vulkan"` (the IREE Vulkan/SPIR-V HAL — served by the iree adapter only; numpy/xla/tvm do not accept it and raise an explicit `BackendError`).
`Device(kind, index)` indices are PER-KIND ENUMERATION indices, not IREE HAL device ids: for cuda/rocm/hip the adapter maps `index` → the HAL's 1-BASED `device_id = index + 1`, while vulkan HAL device ids are QUERIED PER-PROCESS UUID HASHES, so the adapter maps `Device("vulkan", index)` → `query_available_devices()[index]` and creates the device from that info dict — a vulkan index has no ordinal meaning, and an out-of-range index raises an explicit error naming the requested index and the enumerated count.
One HAL device is cached per `(kind, index, runtime_args)` in a THREAD-LOCAL adapter cache shared by `load()` and the placement provider (HAL devices are thread-affine; repeated device creation is slow and leaks).
Compile spelling: a `"vulkan"` device on an iree-family backend infers `target_backends=["vulkan-spirv"]` (there is NO `--iree-hal-vulkan-target`; the optional SPIR-V profile knob is the `vulkan_target` compile option / a raw `--iree-vulkan-target=<profile>`); the artifact label for that target is `"vulkan"`, and a vulkan device only runs an artifact compiled for `vulkan-spirv` (mismatch → explicit `BackendError`, never a silent recompile).
Staging stays honest and kind-neutral: vulkan runs are DEVICE-RESIDENT exactly like cuda/rocm — outputs wrap `IreeDevicePayload` on `Device("vulkan", N)` and are never auto-copied, host inputs are rejected at the run boundary, `.numpy()` on a vulkan output raises with the explicit `.to(cpu)` remedy, and same-device inputs pass through with zero host round-trips.
`Tensor.to(Device("vulkan", N))` goes through a vulkan device-transfer provider the iree adapter registers in BOTH the per-backend and the flat DEFAULT slot; vulkan deliberately does NOT use the CUDA pinned/DMA staging tier (its ordering guarantee is a CUDA-driver property, unverified elsewhere) and takes the plain `asdevicearray` host→device copy instead.
`evoxc.devices("vulkan")` enumerates the IREE Vulkan HAL devices (lazy iree import; returns `[]` — never raises, never invents a device — when iree is absent, the driver cannot initialize, or no device is visible).
`evoxc.devices()` (kind `None`) deliberately lists `cpu + cuda + rocm` only: enumerating vulkan would instantiate the IREE Vulkan runtime and the system Vulkan loader, and on a software-Vulkan host it would report a CPU rasterizer as an accelerator — ask for `devices("vulkan")` explicitly.
Recorded hardware Vulkan coverage is a short Intel Panther Lake (`8086:b0a0`) correctness/residency run through Mesa 26.3.0 ANV on pinned IREE 3.13.0 (five same-device iterations, zero `asdevicearray` calls, 101/101 Vulkan tests, maximum matmul absolute error `1.91e-6`) — evidence only, not general Intel/GPU coverage, performance or model readiness; `./bench/intel_vulkan_findings.md` and `./bench/probe_intel_vulkan.py` hold it. The reproduction recipe, the historical MI300X-host lavapipe validation (`iree-base` 3.13.0 enumerates the Mesa software device unconditionally; pinning `VK_ICD_FILENAMES` is a 3.11-era loader aid) and the default-profile/MI300X limitations live in `./backends/adapters/CONTEXT.md` (Known Issue 16).

## Value model (owned by `core`)

- `evoxc.TensorSpec(shape, dtype, device=None, name=None)`; `evoxc.dim(name_or_int)` → `Dim`; `evoxc.dtype(obj)`; dtype constants `evoxc.float16/float32/float64/int8/int16/int32/int64/uint8/uint16/uint32/uint64/bool_/complex64/complex128` (numpy dtype objects; `bool_` avoids shadowing the builtin).
- Concrete creators `evoxc.tensor(data, dtype=None, device=None)`, `evoxc.zeros/ones/full/empty(shape, dtype=...)`, `evoxc.from_numpy(array)`, `evoxc.from_dlpack(capsule_or_tensor)` are **host-only**: they produce ndarray-backed tensors on `Device("cpu", 0)`, so `device=` accepts only `None`/`Device("cpu", 0)` (anything else → creator-naming `DeviceError`); placing data elsewhere is the explicit post-creation `t.to(device)`.
- `evoxc.constant(tensor) -> SymbolicTensor` — graph-time only, snapshots data, warns above `EVOXC_LARGE_CONSTANT_BYTES` (default 1 MiB). **Snapshots HOST data only**: a non-cpu tensor raises `DeviceError` (no implicit D2H — `t.to(core.Device("cpu", 0))` first). Owned by `ops`; `core` provides the `register_constant_builder` hook `ops` populates.
- Devices: `evoxc.devices(kind=None) -> list[Device]`, `evoxc.split_tensor(tensor, axis, devices)`, `evoxc.replicate_tensor(tensor, devices)` — the latter two are **v1 host-only data preparation** (source ndarray-backed on `Device("cpu", 0)`, every target `Device("cpu", 0)`; anything else → `DeviceError`).

## Tensor ops (owned by `ops`; SymbolicTensor-in/SymbolicTensor-out; Python scalars auto-promote to scalar constants; concrete `Tensor` args raise `TraceError`)

`add, subtract, multiply, divide, power, remainder, maximum, minimum, abs, negate, square, sqrt, exp, log, log1p, sin, cos, tan, tanh, sigmoid, relu, gelu, erf, sign, bitwise_and/or/xor/left_shift/right_shift, logical_and/or/not, cast, equal, not_equal, less, less_equal, greater, greater_equal, select, broadcast, reshape, transpose, slice, gather, scatter, concatenate, pad, reduce_sum, reduce_max, reduce_min, reduce_mean, reduce_prod, sum, max, min, mean, prod, argmax, argmin, dot, conv, tril, triu, cumsum, solve, stop_gradient, runtime_call(callback, *operands, result=TensorSpec...), external_call(name, *operands, result=TensorSpec...)`

`sort, argsort, topk, tile, stack, flip, roll, clamp, diag, isnan, nan_to_num, eye, linspace, matmul, cumprod` (sorting: sort/argsort/topk · structural: tile/stack/flip/roll/diag · numeric: clamp/isnan/nan_to_num · creation: eye/linspace · linalg: matmul/cumprod — design notes in `./ops/CONTEXT.md`)

`eigh, cholesky, qr, matrix_rank, svd, matrix_exp` (linalg factorizations, numpy `linalg` semantics; eigh/qr/svd are multi-result tuple ops; cholesky is lower-triangular, non-PD raises at runtime)

**Control flow** (owned by `trace`): `evoxc.cond(pred, true_fn, false_fn, *operands)`, `evoxc.while_loop(cond_fn, body_fn, init)`, `evoxc.scan(f, init, xs, length=None)` — branch/body functions are traced into IR regions.

**Transforms** (owned by `transforms`, graph→graph): `evoxc.vectorize(graph, axes) -> Graph` (traced Graph only — a bare fn cannot yield a Graph; `TypeError` directs to `evoxc.vmap`), `evoxc.vmap(fn_or_graph, in_axes=0, out_axes=0)`, `evoxc.grad(fn_or_graph, argnums=None)`, `evoxc.jvp(fn_or_graph, tangents)`, `evoxc.vjp(fn_or_graph, cotangents=None)`, `evoxc.batch_functions(fns, axes=0, out_axes=0, *, switch_ops=None, bands=None, alignment="variant")` — with a fn/Defn input these return a `TransformCallable` `(*specs) -> Graph` (transforms never execute); with a Graph input they return a `Graph`. `vjp` cotangents default `None` = scalar-one (single scalar output only). `batch_functions` merges a non-empty list of same-signature programs into ONE graph whose leading axis is a STATIC length-N function axis (row i evaluates program i, bit for bit) and reports merge metadata on `graph.batch_report` (`BatchReport`/`SwitchRecord`); the merge semantics, the two pure-performance strategy options (`bands`, `alignment`), the cost model and the full v1 deferral list (`TransformError`, never a silent fallback) are owned by `./transforms/CONTEXT.md`.

**Distributed** (owned by `dist`): `evoxc.dist.group(name, ranks) -> Group`, `evoxc.dist.all_reduce/all_gather/reduce_scatter/all_to_all/broadcast/collective_permute(tensor, ..., group=Group)`, graph scalars `evoxc.dist.rank()`, `evoxc.dist.world_size()`.

**Sparse tensors** (owned by `sparse`, numpy-backend-only in v1): value model `SparseTensor`, `CSRTensor`, `CSCTensor`, `SparseTensorSpec` (+ `SparseTensorSpec.from_concrete`, the derive-spec entry used by `evoxc.evaluate`), `is_sparse`; creators `coo(indices, values, shape)`, `csr(indptr, indices, values, shape)`, `csc(...)`, `from_dense(dense)` (polymorphic: concrete → eager validated + canonical-form checked; symbolic → in-graph assembly via `from_parts`, `sparse_from_dense` op); converters `to_dense`/`to_csr`/`to_csc`/`to_coo` (polymorphic: concrete → eager, symbolic → graph op); ops `add`, `subtract`, `multiply`, `multiply_dense`, `negate`, `sum` (alias `reduce_sum`, dense result), `transpose`, `reshape`, `concatenate`, `matmul` (sparse@dense and dense@sparse; sparse@sparse → `TraceError` v1 deferral). Pytree contract: ONE registered base class, children = tensor leaves + `dense_shape` ints + `np.dtype` + format string as static leaves, polymorphic unflatten (first child kind selects spec/symbolic/concrete rebuild). v1 deferrals (explicit errors, never silent): no sparse constant, no sparse@sparse, compiler backends defer with an explicit `BackendError` (densify with `evoxc.sparse.to_dense`), whole-sparse `bind`, `concatenate`/`csc` vjp `TransformError`s. Full surface: `./sparse/CONTEXT.md`.

**Random** (owned by `random`; `evoxc/random.py` re-exports the frontend in `evoxc/ops/random.py`): key-based functional RNG as pure graph ops — `key(seed, algorithm="splitmix64")`, `split(key) -> (key_a, key_b)`, `split_n(key, n) -> tuple`, `uniform(key, shape, low=0.0, high=1.0, dtype=float32)`, `normal(key, shape, mean=0.0, std=1.0, dtype=float32)`, `randint(key, shape, low, high, dtype=int32)`, `permutation(key, n, dtype=int32)`, `multinomial(key, input, num_samples)` (int32 output).
**Multi-algorithm framework (binding):** `key()`'s `algorithm` takes a validated string or an `Algorithm` enum member (`SPLITMIX64`/`THREEFRY2X32`/`PHILOX4X32_10`); `ALGORITHMS`/`DEFAULT_ALGORITHM`/`validate_algorithm`/`algorithm_key_type` live in `evoxc/ir/op_defs/random.py` (re-exported at `evoxc.random`).
The algorithm IS the key's static shape/dtype tag — splitmix64 rank-0 int64 (`key(seed)` masks to 64 bits), threefry2x32 `(2,)` int32, philox4x32_10 `(4,)` int32 — so every other random fn takes NO algorithm param and instead infers it from the key operand at trace time, stamping the op's `algorithm` attribute (all 6 OpDefs; unknown → `ValueError`, no matching key form → `ShapeError`/`DTypeError` naming the three forms).
Deterministic/stateless (same key + operands ⇒ BIT-IDENTICAL values across `run`/`evaluate`) and never key-mutating (`split`/`split_n` for independent keys); dtypes default f32 (uniform/normal) / i32 (randint/permutation/multinomial); `key()` is the ONLY polymorphic creator, the rest are graph ops (`TraceError` outside a trace / for concrete `Tensor`s).
numpy is the reference for all 3 algorithms; 5 of 6 ops export as v1 StableHLO (`random_multinomial` defers, `BackendError`); `DEFAULT_ALGORITHM` is `splitmix64` (`evoxc/bench/rng_bench_results.md`); transforms have no random-op rules → `TransformError` (6 OpDefs: category "random", effect "pure", usable in `cond`/`while_loop`/`scan`). Full stream/salt/lowering contract: `./ops/CONTEXT.md` + `./backends/stablehlo/CONTEXT.md`.

**Custom ops** (owned by `block`): `evoxc.block(name, inputs=None, outputs=None, attributes=None, effects=None, batching=None, portable=None)` — decorator/factory returning a callable `BlockOp`; `BlockOp.impl(backend_name)`; `BlockOp.batching_rule(fn)`; `BlockOp.jvp_rule/vjp_rule(fn)`. No rule + no safe policy + no portable decomposition ⇒ `TransformError`.

**Backends** (owned by `backends`): `evoxc.backends.Backend` (abstract: `name`, `capabilities`, `lower`, `compile`, `load`), `evoxc.backends.register/get(name)`, `evoxc.backends.numpy_backend` (default CPU interpreter), `evoxc.backends.stablehlo` (`export(graph|module) -> str` MLIR text). `evoxc.lower/compile/load` default to `numpy_backend`.

**Persistence** (owned by `persist`, used by pipeline types): `Graph.save/load`, `LoweredProgram.save/load/.text()`, `CompiledArtifact.save/load`, `Executable.save/load`, `evoxc.Cache` (explicit; `FileCache(directory)` in `persist`). Loading never silently re-traces/recompiles; incompatibility fails clearly.

**Namespace**: `evoxc.numpy` (alias `enp`) + `evoxc.numpy.linalg` — numpy-style graph API producing the same IR as `ops`.

**Structured I/O**: tuple/list/dict/namedtuple/dataclass supported everywhere (trace inputs, run outputs, bind); custom containers register via `evoxc.register_pytree_node`. **Pytree utilities** (owned by `core`, exported on `evoxc`): `tree_map(fn, *trees)`, `tree_leaves(tree)`, `tree_structure(tree)`, `tree_flatten(tree)`, `tree_unflatten(leaves, treespec)` — pure sugar over flatten/unflatten (no new semantics). Container edge behavior: `defaultdict`/`Counter` roundtrip (default_factory preserved when `None`/a class, else a clear `unflatten` error); unorderable dict keys, dataclass `InitVar`/`init=False` rebuilds, and `register_pytree_node(object, ...)` raise plain `TypeError`/`ValueError` with actionable messages. **Structure-mismatch diagnostics**: every structural mismatch (`tree_map`, `Graph.flatten_inputs`/`validate_inputs`, `run`/`bind`, transforms' axes/tangent trees) reports the first divergent pytree path with expected/got node descriptions (e.g. `first mismatch at pytree path [0]['z']: expected dict with keys ['a', 'b'], got list of length 3`) via the shared `core.first_mismatch_path`/`format_path` helpers; per-caller lead-in wording is preserved (tests match the substrings).

## Value-model details (binding)

- **Errors**: all public errors derive from `EVOXCError` (in `core`): `TraceError`, `ShapeError`, `TransformError`, `BackendError`, `PersistenceError`, `DeviceError`, `DTypeError`, `VerificationError`, `BlockError`. No API silently swallows or works around errors; messages include the source location (`model.py:83`) whenever a graph location exists.
- **Shapes**: `Dim(name)` symbolic; `DimExpr` supports `+ - * // % min max` over dims/ints; `TensorSpec.shape` = tuple of `Dim|DimExpr|int|None` (`None` = runtime-dynamic, unchecked). Rank is always known at trace time. Shape inference is `ir`/`ops`'s job via `DimExpr` arithmetic.
- **`Tensor`** — a local physical tensor whose `device` is always physically true (ndarray data IS host memory at `Device("cpu", 0)`, a payload takes the payload's device, and an explicit `device=` must agree). `.numpy()` is explicit host access (zero-copy for ndarray data, a fresh host copy per call on a cpu-kind payload, `DeviceError` on a non-cpu payload — `t.to(core.Device("cpu", 0)).numpy()`). `__dlpack__`/`__dlpack_device__` are zero-copy for host data and DELEGATE to a device payload's optional DLPack export protocol (`__dlpack__(stream=None, max_version=None, copy=None, dl_device=None)`; `IreeDevicePayload` exports its HAL buffer zero-copy, `torch.from_dlpack(t)` sharing memory), else a kind-aware `DeviceError`; `__eq__` is metadata-only with a payload. `Tensor.to(device)` is the ONLY transfer API (equal device → `self`; `to(cpu)` = explicit D2H; `to(non-cpu)` uses the provider registry, owning backend's slot then flat DEFAULT, missing → `DeviceError`; direct payload→non-cpu → `DeviceError` suggesting `t.to(cpu).to(target)`). Mutable `data` is unsupported for graph constants. Detail: `./core/CONTEXT.md`.
- **Run boundary (no implicit device↔host transfers)**: `evoxc.run`/`evoxc.bind` reject any tensor leaf whose `device` differs from the executable's device with a `DeviceError` naming the input tree path, both devices, "no implicit device", and `t.to(` — BEFORE backend dispatch. A non-cpu executable therefore rejects host numpy inputs and raw ndarrays: host inputs must be explicitly placed (`x.to(Device("cuda", 0))`, `x.to(Device("vulkan", 0))`, …). Run outputs stay device-resident (never auto-copied); read back via `t.to(cpu).numpy()`. llvm-cpu runs keep feeding/reading host data (their tensors are cpu:0).
- **`SymbolicTensor`**: fields `value` (ir.Value), `dtype`, `shape` (tuple of `DimExpr|int`), `location`; SSA identity = `value.id`. Must NOT define `numpy`, `data_ptr`, `__dlpack__`, `__array__`.
- **`Graph` trace semantics**: parameters become `Function` block args; static Python values specialize and are recorded in `static_values` (run validates them); a closure-captured `Tensor` used in ops → `TraceError` ("make it an explicit input or use evoxc.constant"); `evoxc.constant` creates a Constant op and warns above `EVOXC_LARGE_CONSTANT_BYTES`.
- **Staged sugar rules**: `evoxc.build`/`evoxc.evaluate`/`evoxc.build_cached` docstrings must state their exact expansion; no other composition APIs exist in core.

## Serialization contract (binding)

Formats are versioned via constants (`EVOXC_FORMAT_VERSION`). Artifacts are self-describing: backend name/version, target, input/output signature (TreeSpec + specs), static values, required custom ops, IR format version. `Graph.save` → `.evoxcgraph` (portable JSON container); `LoweredProgram` numpy → serialized program; stablehlo → `.mlir` text; `CompiledArtifact` → `.evoxcartifact`; `Executable.save` → backend-dependent (numpy saves the artifact plus an explicit note that it is reconstructed at load). Loading with a mismatched backend/device/ABI → `PersistenceError`, never a silent recompile.

## evoxc.io — explicit async host-data IO (user-facing module)

`evoxc.io` (module `evoxc/io.py`; stdlib + `evoxc.core` imports ONLY) is explicit copy-queue sugar over `Tensor.to`: it schedules the SAME explicit transfers `Tensor.to` performs synchronously onto a background worker thread, so they run off the calling thread. No hidden staging and no overlap guarantees beyond caller-relative asynchrony: ONE process-global FIFO daemon worker thread (lazily started at the first submission) executes every scheduled copy strictly in issue order — a v1 limitation (true same-device overlap needs runtime async-engine support; see Known Issue #12 in `./backends/adapters/CONTEXT.md`). The worker never dies and never raises: per-copy failures are stored on the handle and re-raised by every `wait()`/`result()`/`wait_all()`.
- `prefetch(host_tensor, device) -> AsyncCopy` — host→device, run through the registered device-transfer provider; the source must be an ndarray-backed `core.Tensor` on `Device("cpu", 0)` (a raw ndarray → `TypeError` telling you to wrap it; a payload-backed host tensor, or a source already at the target, → `DeviceError`; a non-`core.Device` target → `TypeError`).
- `sink(device_tensor) -> AsyncCopy` — device→host, via the payload host-copy path (an ndarray-backed source, or a cpu-kind payload, → `DeviceError` pointing at `t.numpy()` / "no download needed").
- class `AsyncCopy` — `.device` (the target for prefetch, the source for sink), `.direction` (exactly `"host_to_device"` or `"device_to_host"`), `.done` (non-blocking poll), `.wait(timeout=None)` (blocks until the copy finishes and re-raises any stored failure VERBATIM on every call; a timeout raises `TimeoutError` and NEVER cancels the copy — wait again to retry), `.result(timeout=None)` (= `wait()` + the copied tensor). No destructor: GC never auto-waits, and a dropped handle's copy completes independently.
- `wait_all(timeout=None)` — waits for every copy outstanding at call time in issue order, raising the first stored failure.
Schedule-time validation is synchronous on the calling thread; runtime failures surface verbatim at `wait()`/`result()`/`wait_all()`. Re-entry guards: scheduling or waiting from the worker thread would deadlock, so `prefetch()`/`sink()`/`AsyncCopy.wait()`/`wait_all()` there raise `RuntimeError`. Non-cpu-kind copies trigger a lazy, best-effort, one-time CUDA/ROCm primary-context bootstrap on the worker (a throwaway iree HAL device with the adapter's exact 1-based `device_id = index + 1` mapping, on the iree DRIVER name — `rocm`/`hip` → `hip`, else the kind as-is; kept alive in `_bootstrap_devices`; every bootstrap failure is swallowed so it can never mask the copy's own error). Numpy-only environments never import iree. The `atexit` hook drains in-flight copies best-effort and stops the worker cleanly; interpreter exit never blocks.

## Memoized build sugar (evoxc.build_cache)

`evoxc.build_cached(fn, *specs, backend=None, device=None, cache=None, **options) -> Executable` (module `evoxc/build_cache.py`) is documented shorthand for a MEMOIZED `build` — no other behavior: the exact `trace → lower → compile → load` composition runs at most once per distinct cache key, and a hit returns the SAME fully loaded `Executable` with zero pipeline work. Purpose: a true-JIT-style helper for meta-level loops (NAS / genetic programming / genetic algorithms) whose outer loop produces a DIFFERENT static program each iteration (e.g. a random expression tree encoded as a tensor), decodes it, traces + compiles a fresh graph at runtime, and runs it in an inner loop; the returned executable is a NORMAL one (same-device device-resident run loops work unchanged) and static args stay in the run signature, validated at the run boundary.
- **Cache key** — computed BEFORE any tracing as the tagged tuple `(("fn", id(fn)), ("specs", specs), ("backend", resolved_backend.name), ("device", resolved_device), ("options", _canonicalize_options(resolved_options)))`; the entry pins `fn` as its keepalive so `id(fn)` can never alias a later object. The full specs tree (structure AND static content) is encoded via `persist.encode_value`, so each distinct static "program" value = a distinct graph = a distinct entry, while a runtime tensor in a program slot is an ordinary graph input keyed ONCE on its `TensorSpec` — never specialized per value. Options are canonicalized order-insensitively so semantically-equal option sets key identically; unset `backend`/`device` resolve exactly as in `build` and participate in the key. Process-env knobs the compiler stages read themselves (`EVOXC_OPT_LEVEL`, `EVOXC_EIGH_ALGORITHM`, `EVOXC_SPLIT_REDUCTION`, `EVOXC_IREE_*`, `EVOXC_XLA_*`, `EVOXC_TVM_*`) are NOT part of the key — clear the cache (or pass a fresh `CompileCache`) when changing them. An unencodable static leaf raises a pre-cache `TypeError` naming the key component path (e.g. `specs[2]`, `specs[3]['w']`) and its type, pointing at `persist.encode_value`'s coverage and at plain `evoxc.build` for unkeyable calls.
- **Failure bookkeeping (binding)** — fn validation, backend/device resolution, cache-type checks and encodability all fire BEFORE any cache access; env-resolution failures count NO miss and insert nothing; post-key stage failures count a miss, insert nothing, and re-raise untouched. Only a fully loaded Executable is ever inserted — never a cached failure, never an eager fallback.
- class `CompileCache(Cache)` — in-memory thread-safe LRU (default `maxsize=128`; a non-positive or non-int `maxsize` → `ValueError`): `get`/`put`/`contains`/`clear`/`get_or_compute` plus public `hits`/`misses` (`clear` resets them); the compute function runs OUTSIDE the lock and the first insert wins on races; LRU eviction pops the oldest entry. In-memory only (executables hold device handles/vmfb/compiled code — never persisted). `cache=None` selects the module-level default (a fresh instance isolates callers); there is deliberately NO `cache=False` escape — plain `evoxc.build` is the no-cache path. `cache` must be a `CompileCache` or `None` and `fn` a callable/`@evoxc.defn` function — a `Graph` argument raises a `TypeError` directing to the explicit `lower`/`compile`/`load` pipeline.

## External kernels (binding interface contract)

A kernel-agnostic escape hatch for plugging custom triton kernels into `defn` graphs; **no kernel code lives in evoxc**.

**1. Graph side — `evoxc.external_call(name, *operands, result=...)`** (`evoxc/ops/external.py`; IR op `external_call`, effect `callback`): `name` is a non-empty `str` STATIC identifier (tracing needs no registration, running does); operands are `SymbolicTensor`s or Python scalars (0-d constants; no static params in v1); `result` is a `core.TensorSpec` or non-empty tuple/list — the DECLARED output contract (symbolic dims or `None`) — returning a `SymbolicTensor` or tuple. Errors: `TraceError` outside a trace / for concrete `Tensor` operands, `TypeError` for a bad `name`/`result`; works inside `cond`/`while_loop`/`scan` bodies on numpy.

**2. Run-time registry (`evoxc/external.py`, stdlib-only module-level imports)**:
- `register_external_kernel(name, callable_, backend=None, device_resident=False) -> ExternalKernel` — process-global PER-BACKEND slots (`None` = the DEFAULT slot), last registration wins callable AND mode; `device_resident=True` requires an explicit backend slot (`TypeError` with `backend=None`; iree-only in v1). `TypeError` on a non-str/empty or reserved-suffix name (`_EVOXC_BATCH_SUFFIX`, `"__evoxc_batched"`, reserved for `batch_variant`), a non-callable kernel, a non-bool `device_resident`, or a non-None/non-str backend.
- class `ExternalKernel` (attr `name`; methods return `fn`): `impl(backend, fn=None, device_resident=False)`, `portable(fn)` (= `register_portable`), `batching_rule`/`vjp_rule`/`jvp_rule` (rules under `external:<name>`); `batch_variant(fn=None, *, backend=None, device_resident=False)` registers `f"{name}__evoxc_batched"` plus the pass-through batching rule under both names, while `batch_invariant()` (returns `self`) installs it under `external:<name>` only.
- `register_portable(name, fn)` — OPTIONAL decomposition; an `@evoxc.defn` (`__evoxc_defn__` validated), traced LAZILY when a fallback fires (vjp always, batching only when no explicit rule exists); `get_portable(name)` → it or `None`; `unregister_external_kernel(name)` drops all slots, the portable and its derived form (`KeyError` if never registered).
- **Callable signature (binding). HOST mode (default)**: `fn(*np_arrays) -> ndarray | core.Tensor | tuple/list of them`, count/dtype/shape matching the declared specs (count/dtype → `BackendError`, shape → `ShapeError`, else `BackendError`). **DEVICE mode** (`device_resident=True`, iree only): `fn(*tensors)` gets the boundary's device `core.Tensor`s (`.data` an `IreeDevicePayload`) and may return device tensors, duck-typed payloads (`shape`/`dtype`/`device`/`to_host()`), raw `DeviceArray`s, **DLPack-capable objects (a `torch.Tensor` imported zero-copy via `HalDevice.from_dlpack_capsule` after its `__dlpack_device__` matches the run's device; another device → `BackendError`)**, numpy arrays, or mixes — METADATA-ONLY validated by `evoxc/backends/external_validate.py`.

**Zero-copy interop**: `core.Tensor.__dlpack__`/`__dlpack_device__` delegate to `IreeDevicePayload`, so `torch.from_dlpack(tensor)` shares the HAL buffer (zero-copy, mutation mutual). **Synchronization is the kernel's responsibility** (iree's HAL has its own stream, no fence added, so pending work must `torch.cuda.synchronize()`; export is safe because `run` blocks); `copy=True` and a different `dl_device` raise `DeviceError`s, and a dtype the HAL cannot express natively refuses the export — read back via `t.to(cpu)`.

**Execution (v1)**: the numpy interpreter dispatches by name via `get_external_kernel_entry(name, "numpy")` — a `device_resident=True` or unknown slot raises `BackendError`. **External-kernel boundaries are the ONLY sanctioned host↔device staging points.**

**Transforms**: rules live under `external:<name>`; without explicit rules a registered PORTABLE drives `vmap`/`vectorize`/`grad`/`jvp`/`vjp` through the fallbacks (`evoxc/external_rules.py`), else `TransformError`; the pass-through batching rule rebuilds each mapped `external_call` with the `target_name` attribute and the batched operand stack AS-IS — leading batch dims on result types, `"result_specs"` re-encoded as `ir.ValueType`s, `MappedAxes(range(k))`.

**Persistence**: the registry is NEVER serialized (artifacts carry only `name`); `Graph.save`/`load` need the kernels re-registered; numpy `compile()` records names in `required_custom_ops` (resolved LAZILY).

**Compiler backends**: iree declares `Capabilities.external_calls=True`, SPLITS the graph at `lower()` into segments + a kernel-call plan and dispatches each boundary in its registered mode (host staging via `Tensor.to(cpu)`, or zero-host-round-trip device dispatch); xla/tvm inline a registered portable with a `UserWarning` else raise `BackendError`, and stablehlo direct export defers (`DEFERRED_OPS`). Details: `./backends/CONTEXT.md`.

Minimal usage:
```python
evoxc.register_external_kernel("relu_custom", my_kernel)   # default (host) slot
evoxc.register_external_kernel("relu_cuda", my_kernel, backend="iree", device_resident=True)

@evoxc.defn
def model(x, w):
    return evoxc.dot(evoxc.external_call("relu_custom", x,
                    result=evoxc.TensorSpec((N, D), evoxc.float32)), w)

evoxc.evaluate(model, x_np, w_np, backend="iree")   # llvm-cpu split + host dispatch
exe = evoxc.build(model, spec_x, spec_w, backend="iree", device=evoxc.Device("cuda", 0))
host = evoxc.run(exe, x_cuda, w_cuda)[0].to(evoxc.Device("cpu", 0)).numpy()  # explicit D2H
```

Zero-copy device kernel (Triton or any torch-side launcher), on the ROCm/CUDA device it runs on:

```python
import torch

def triton_kernel(x, w):            # receives device core.Tensors, no host staging
    tx, tw = torch.from_dlpack(x), torch.from_dlpack(w)   # zero-copy DLPack import
    out = launch_my_triton_kernel(tx, tw)                  # returns a torch.Tensor
    torch.cuda.synchronize()        # REQUIRED: iree's HAL has its own stream
    return out                      # adapter imports it back zero-copy

evoxc.register_external_kernel("my_triton", triton_kernel,
                               backend="iree", device_resident=True)

@evoxc.defn
def graph(x, w):
    return evoxc.external_call("my_triton", x, w,
                               result=evoxc.TensorSpec((N, D), evoxc.float32))

exe = evoxc.build(graph, spec_x, spec_w, backend="iree", device=evoxc.Device("rocm", 0))
out = evoxc.run(exe, x_rocm, w_rocm)          # stays device-resident
out_torch = torch.from_dlpack(out)            # the export side, also zero-copy
```

## Notes for agents

- Keep modules thin and single-purpose; files under ~1000 lines (split along declared boundaries instead).
- Shared capability goes to the lowest common ancestor module per the contracts above — do not duplicate (e.g. numpy kernels live ONLY in `backends/numpy`).
- `evoxc/__init__.py` re-exports this exact surface; when adding a public name, update `__init__.py` and this contract together.
- Function-transform integration is narrower than ordinary callable staging: `pipeline.build` and `build_cache.build_cached` always invoke `trace(fn, *specs)` and have no graph-provider dispatch, while `transforms.TransformCallable` consumes specs and returns a standalone Graph rather than symbolic trace outputs.
- The tracer has no transformed-callable/graph-provider protocol or graph-inlining service, so accepting a transform wrapper through the callable type check does not establish compatibility with `build` or invocation inside an active trace; verified mechanics and source-derived gaps belong to `./trace/CONTEXT.md` and `./transforms/CONTEXT.md`.
- Keep this file to the API contract + routing table: new per-feature detail belongs in the owning child node's CONTEXT.md plus a routing-table row here.
- **`./_native_codec.py` is the private v1 envelope codec** between a Python `ir.Module` and the neutral in-process dict in `../native/CONTEXT.md` — `ENVELOPE_FORMAT = 1`, `encode_module`/`decode_module`, `encode_type`/`decode_type`; it is NOT the persistence format (`./persist` stays the v1 on-disk format) and imports only `evoxc.core`, `evoxc.ir`, numpy and stdlib.
- **`./_native.py` is the optional Rust/PyO3 loader and typed façade**: it finds `evoxc/_evoxc_native*.so` (or `EVOXC_NATIVE_LIB`) lazily behind a lock, exposes `available()`/`require()`/`version()`/`infer()`/`transform()`/`batch_functions()` plus the read-only `batching_rule_keys()`, and maps `NativeError.kind` onto the `evoxc.core` public error family verbatim — `import evoxc` never requires the extension, `evoxc.transforms` delegates all six builtin transforms to `transform()`/`batch_functions()`, and `infer()` is consumed by the native inference parity harnesses while trace-time inference still runs in Python (`ir/inference.py`).
- **`run`'s per-call host cost is leaf-driven, not graph-driven** — per-IO leaf ≈2–3.5 µs, per-op ≈0 (pytree nesting irrelevant), `_prepare_flat_inputs`/`_unflatten_outputs` ≈24–31 µs with the backend invoke dominating; both halves are plan-driven and plans cache metadata only, never values (per-leaf dtype/shape/device + pre-sized output slots, one tuple compare for all-static shapes, path strings only on the failure branch, `core.Tensor` outputs passed through untouched), and no validation or error message is ever skipped.
- **Measured at 12 in/12 out** (`evoxc.run`, warm best-of-240; compare deltas, absolute levels drift ~10 % on a shared MI300X VF): iree/rocm −17.7 µs (−12.8 %), xla/rocm −7.2 µs (−6.0 %), iree llvm-cpu −16.5 µs (−17.1 %), numpy/cpu −0.9 µs (control; pipeline share alone 33.8 → 28.1 µs); per-output slope iree 5.3 → 4.4, xla 4.6 → 4.2, llvm-cpu 3.8 → 2.7 µs.
- The full stage ladder, bare-metal bounds and the remaining levers (PJRT async execute events; `core.unflatten` ≈4.7 µs of the ≈5 µs unflatten) live in `./backends/adapters/CONTEXT.md` Known Issue 14; don't re-derive them.
- **numpy staging deserializes at most ONCE per process**: `lower` attaches the verified module, the exact payload object and the collected custom-op names to the `LoweredProgram` as private NON-persisted attributes, `compile`/`load` reuse them behind a payload-identity check (a disk-loaded program/artifact falls back to one decode), the persisted container bytes are unchanged, and the post-inline `graph.verify()` is skipped when `inline_portables` spliced nothing; the test seam is `evoxc.backends.numpy._decode_payload` plus `decode_stats()`/`reset_decode_stats()`, and the measured staging cost lives in `./backends/CONTEXT.md`.
