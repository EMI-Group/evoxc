This page is the map of the `evoxc` namespace: which names exist, which area owns them, and which guide explains them.
It exists because the generated API tree cannot cover the namespace itself — `evoxc.__all__` is computed at import time from the module globals, and a static analyser cannot evaluate that.

Per-symbol signatures, module paths and docstrings are on the generated pages under [`/api/`](/api/), grouped by module and addressed as `/api/<module-path>/<symbol>/`.
Where a name below is a link, it goes to the page that owns it — often a definition module such as [`evoxc.core`](/api/evoxc/core/), [`evoxc.pipeline`](/api/evoxc/pipeline/) or [`evoxc.backends`](/api/evoxc/backends/), not the area it is grouped under here.

## Staging and the pipeline

Everything that moves a program from a Python function to a runnable object.

| Name | What it gives you |
|---|---|
| `evoxc.defn` | decorator marking a function as a graph *definition* → [`Defn`](/api/evoxc/trace/defn/) |
| [`evoxc.trace(fn_or_defn, *specs)`](/api/evoxc/trace/trace/) | [`Graph`](/api/evoxc/trace/graph/) — EvoXIR, input/output trees, snapshotted static values |
| [`evoxc.lower(graph, backend=None, **options)`](/api/evoxc/pipeline/lower/) | [`LoweredProgram`](/api/evoxc/backends/loweredprogram/) |
| [`evoxc.compile(lowered, backend=None, **options)`](/api/evoxc/pipeline/compile/) | [`CompiledArtifact`](/api/evoxc/backends/compiledartifact/) |
| [`evoxc.load(artifact, backend=None, device=None, **options)`](/api/evoxc/pipeline/load/) | [`Executable`](/api/evoxc/backends/executable/) |
| [`evoxc.run(executable, *args, **options)`](/api/evoxc/pipeline/run/) | the output tree, in the shape you passed in |
| [`evoxc.bind(executable, **bindings)`](/api/evoxc/pipeline/bind/) | [`BoundExecutable`](/api/evoxc/pipeline/boundexecutable/) — argument-supply sugar, never a graph change |
| [`evoxc.build(fn, *specs, backend=None, device=None, **options)`](/api/evoxc/pipeline/build/) | `Executable` — documented `trace → lower → compile → load` |
| [`evoxc.evaluate(fn, *args, backend=None, device=None, **options)`](/api/evoxc/pipeline/evaluate/) | documented `derive specs → build → run` |
| [`evoxc.build_cached(fn, *specs, backend=None, device=None, cache=None, **options)`](/api/evoxc/build-cache/build-cached/) | memoized `build`, keyed before tracing |
| [`evoxc.compile_text(mlir_text, input_specs, output_specs, *, backend=None, device=None, entry_functions=("main",), **options)`](/api/evoxc/pipeline/compile-text/) | `Executable` from StableHLO text, bypassing `lower` |
| [`evoxc.CompileCache`](/api/evoxc/build-cache/compilecache/) | the in-memory LRU backing `build_cached` (default `maxsize=128`) |
| [`evoxc.Executable`](/api/evoxc/backends/executable/), [`evoxc.BoundExecutable`](/api/evoxc/pipeline/boundexecutable/) | the pipeline wrapper types ([details](/reference/pipeline-objects/)) |

Guides: [Graphs and tracing](/guides/graphs-and-tracing/), [Persistence and caching](/guides/persistence-and-caching/) for `build_cached`/`CompileCache`, [Custom ops and kernels](/guides/custom-blocks/) for `compile_text`.

## The value model

| Name | Meaning |
|---|---|
| [`evoxc.Tensor`](/api/evoxc/core/tensor/) | materialized runtime tensor — has storage, a concrete shape, a *physical* device |
| [`evoxc.TensorSpec(shape, dtype, device=None, name=None)`](/api/evoxc/core/tensorspec/) | describes a future runtime tensor; holds no data |
| [`evoxc.SymbolicTensor`](/api/evoxc/core/symbolictensor/) | an SSA value inside a graph; no data, no `.numpy()` |
| [`evoxc.Device(kind, index=0)`](/api/evoxc/core/device/) | a physical device; kinds `cpu`, `cuda`, `rocm` (alias `hip`), `vulkan` |
| [`evoxc.dim(name_or_int)`](/api/evoxc/core/dim-function/) | [`Dim`](/api/evoxc/core/dim/) — a named symbolic extent; [`DimExpr`](/api/evoxc/core/dimexpr/) arithmetic comes from it |
| [`evoxc.dtype(obj)`](/api/evoxc/core/dtype/) | normalize anything dtype-like to a numpy dtype |
| `evoxc.float16` … `evoxc.complex128` | the 14 dtype constants: `float16/32/64`, `int8/16/32/64`, `uint8/16/32/64`, `bool_`, `complex64/128` |
| [`evoxc.tensor`](/api/evoxc/core/tensor-function/), [`evoxc.zeros`](/api/evoxc/core/zeros/), [`evoxc.ones`](/api/evoxc/core/ones/), [`evoxc.full`](/api/evoxc/core/full/), [`evoxc.empty`](/api/evoxc/core/empty/), [`evoxc.from_numpy`](/api/evoxc/core/from-numpy/), [`evoxc.from_dlpack`](/api/evoxc/core/from-dlpack/) | concrete creators — host data only, always `Device("cpu", 0)` |
| [`evoxc.constant(tensor)`](/api/evoxc/core/constant/) | the only way to embed data in a graph; graph-time only, warns above `EVOXC_LARGE_CONSTANT_BYTES` |
| [`evoxc.devices(kind=None)`](/api/evoxc/core/devices/) | enumerate devices; never raises, never invents one |
| [`evoxc.split_tensor(tensor, axis, devices)`](/api/evoxc/core/split-tensor/), [`evoxc.replicate_tensor(tensor, devices)`](/api/evoxc/core/replicate-tensor/) | v1 host-only data preparation, not a sharding transformation |

Guides: [Core concepts](/getting-started/core-concepts/) for the four value kinds, [Tensors and devices](/guides/tensors-and-devices/) for placement, `Tensor.to` and DLPack.

## Pytree helpers

Structured I/O is a first-class part of the contract: tuple, list, dict, namedtuple and dataclass work everywhere (trace inputs, run outputs, bind).

| Name | Purpose |
|---|---|
| [`evoxc.flatten(tree)`](/api/evoxc/core/flatten/), [`evoxc.unflatten(leaves, treespec)`](/api/evoxc/core/unflatten/) | the primitive pair |
| `evoxc.tree_flatten(tree)`, `evoxc.tree_unflatten(leaves, spec)` | aliases of the same pair |
| `evoxc.tree_map(fn, *trees)` | map over leaves with structure validation |
| `evoxc.tree_leaves(tree)` | leaves in pre-order |
| `evoxc.tree_structure(tree)` | the [`TreeSpec`](/api/evoxc/core/treespec/) of a tree |
| [`evoxc.register_pytree_node(node_type, flatten_fn, unflatten_fn)`](/api/evoxc/core/register-pytree-node/) | register a custom container |
| `evoxc.TreeSpec` | the recorded structure itself |

Structural mismatches report the first divergent path with expected and got descriptions; the diagnostics are shared by `tree_map`, `run`, `bind` and the transforms' axes/tangent trees.

## Ops and the numpy namespace

| Name | What it is |
|---|---|
| [the frontend ops](/api/evoxc/ops/) | `add`, `dot`, `sum`, `reshape`, `conv`, `sort`, `eigh`, `matmul`, … — the complete list is on the [Op catalogue](/reference/ops/) |
| [`evoxc.runtime_call(callback, *operands, result=...)`](/api/evoxc/ops/runtime-call/) | an explicit host callback at run time |
| [`evoxc.external_call(name, *operands, result=...)`](/api/evoxc/ops/external-call/) | a named external kernel boundary |
| [`evoxc.custom_call(call_target_name, *operands, result, ...)`](/api/evoxc/ops/custom-call/), [`evoxc.inline_stablehlo(body, *operands, result, ...)`](/api/evoxc/ops/inline-stablehlo/) | compiler-only escape hatches, gated by [`Capabilities.custom_ops`](/api/evoxc/backends/capabilities/) |
| [`evoxc.numpy`](/api/evoxc/numpy/) (alias `evoxc.enp`) and `evoxc.numpy.linalg` | numpy-style spelling of the same IR |
| [`evoxc.arange`](/api/evoxc/numpy/arange/) | the one creation op exported at top level (a graph `Constant`; the concrete creators are `zeros`/`ones`/`full`/`empty`) |

Op functions build into the active trace. Called with a `SymbolicTensor` they build IR; called with a concrete `Tensor`, or outside a trace, they raise `TraceError` — there is no eager mode.

## Transforms

| Name | Signature shape |
|---|---|
| [`evoxc.vectorize(graph, axes)`](/api/evoxc/transforms/vectorize/) | traced `Graph` in, `Graph` out |
| [`evoxc.vmap(fn_or_graph, in_axes=0, out_axes=0)`](/api/evoxc/transforms/vmap/) | sugar over `vectorize` |
| [`evoxc.grad(fn_or_graph, argnums=None)`](/api/evoxc/transforms/grad/) | reverse-mode gradient as an ordinary graph |
| [`evoxc.jvp(fn_or_graph, tangents)`](/api/evoxc/transforms/jvp/) | forward-mode |
| [`evoxc.vjp(fn_or_graph, cotangents=None)`](/api/evoxc/transforms/vjp/) | reverse-mode with explicit cotangents |
| [`evoxc.batch_functions(fns, axes=0, out_axes=0, *, switch_ops=None, bands=None, alignment="variant")`](/api/evoxc/transforms/batch-functions/) | merges same-signature programs into one graph |
| [`evoxc.split_by_inputs(graph_or_fn, fixed=None, *, fixed_leaves=None)`](/api/evoxc/transforms/split-by-inputs/) | one graph sliced into a `prepare` half (its fixed inputs) and an `apply` half (its varying inputs); a `Graph` in, a [`SplitPlan`](/api/evoxc/transforms/splitplan/) out |
| [`evoxc.analyze_inputs(graph)`](/api/evoxc/transforms/analyze-inputs/) | [`InputAnalysis`](/api/evoxc/transforms/inputanalysis/): per tensor input, its consumers, the ops that depend on it, the outputs it influences, and what fixing it alone would cost |
| `evoxc.BoundaryValue`, `evoxc.InputInfo`, `evoxc.SplitCallable` | the split's boundary, per-input and callable types ([details](/reference/pipeline-objects/)) |
| [`evoxc.BatchReport`](/api/evoxc/transforms/batchreport/), [`evoxc.SwitchRecord`](/api/evoxc/transforms/switchrecord/) | the merge metadata reported on `graph.batch_report` |
With a function or `Defn` the numeric transforms give a [`TransformCallable`](/api/evoxc/transforms/transformcallable/) (`*specs → Graph`) and the split gives a `SplitCallable` (`*specs → SplitPlan`); with a `Graph` the result is a `Graph` — except the split, which returns a `SplitPlan` holding two of them. Transforms never execute anything. Guide: [Graph transforms](/guides/graph-transforms/).
The five numeric transforms and the `batch_functions` merge are the Rust engine; `split_by_inputs` and `analyze_inputs` are the one structural (non-numeric) pass and live in Python because they only slice the graph data structure.

## Error taxonomy

Every public error derives from [`evoxc.EVOXCError`](/api/evoxc/core/evoxcerror/), and messages include the source location (`model.py:83`) whenever a graph location exists.

| Class | Raised when |
|---|---|
| [`TraceError`](/api/evoxc/core/traceerror/) | tracing misuse: no active trace, a concrete `Tensor` operand, a closure-captured tensor, a bad static value, a symbolic-length `scan` |
| [`ShapeError`](/api/evoxc/core/shapeerror/) | a shape or axis contract is violated (at trace time or run time) |
| [`DTypeError`](/api/evoxc/core/dtypeerror/) | a dtype contract is violated |
| [`TransformError`](/api/evoxc/core/transformerror/) | a transform cannot answer: missing batching/derivative rule, unsupported axis or op — never a silent fallback |
| [`BackendError`](/api/evoxc/core/backenderror/) | a backend refuses: unknown option key, unsupported op, unavailable adapter, invalid option value |
| [`DeviceError`](/api/evoxc/core/deviceerror/) | placement is wrong: an implicit transfer would be needed, `.numpy()` on a device payload, a creator asked for a non-host device |
| [`PersistenceError`](/api/evoxc/core/persistenceerror/) | a save/load container mismatch, wrong payload type, or an artifact/backend disagreement |
| [`VerificationError`](/api/evoxc/core/verificationerror/) | the IR fails `verify()` |
| [`evoxc.block.BlockError`](/api/evoxc/block/blockerror/) | a block declaration or implementation problem |

Plain `TypeError` / `ValueError` / `NotImplementedError` are reserved for Python-level argument misuse (a wrong stage object, a non-`TensorSpec` in a spec sequence, an unsupported `norm` order) and are listed per symbol on the generated pages.
