Each stage of an evoxc program returns a distinct public type.
There is no "any stage" object and no function that inspects what it was handed and performs whatever steps are missing — a mismatched stage is a `TypeError` naming both the expected type and the function that produces it.

```text
@evoxc.defn ───────────────────────────────▶ Defn
Defn + specs ──evoxc.trace────────────────▶ Graph              (EvoXIR module + trees + static values)
Graph ────────evoxc.vectorize / vmap / grad / jvp / vjp / batch_functions
                                            ──▶ Graph            (an ordinary graph of ordinary ops)
Graph ────────evoxc.split_by_inputs──────────▶ SplitPlan          (prepare + apply Graphs, a boundary)
Graph ────────evoxc.lower─────────────────▶ LoweredProgram     (StableHLO text or backend payload)
LoweredProgram ──evoxc.compile────────────▶ CompiledArtifact   (vmfb / PJRT executable / serialized program)
CompiledArtifact ──evoxc.load─────────────▶ Executable         (device-bound)
Executable + tensors ──evoxc.run──────────▶ Tensor (tree)
Executable + named tensors ──evoxc.bind───▶ BoundExecutable
```

[`evoxc.build`](/api/evoxc/pipeline/build/) is that whole chain in one documented call, [`evoxc.evaluate`](/api/evoxc/pipeline/evaluate/) adds the run, and [`evoxc.build_cached`](/api/evoxc/build-cache/build-cached/) memoizes the chain. [`evoxc.compile_text`](/api/evoxc/pipeline/compile-text/) enters at `compile` with StableHLO text of your own and never traces or lowers.

## Which stage is inspectable how

Every helper below is a pure read: none traces, compiles, executes, transfers or mutates anything, and every dict-returning helper is JSON-safe.

| Object | `repr` | `summary()` | `text()` | `source_text()` | `plan_text()` | save / load |
|---|---|---|---|---|---|---|
| [`Defn`](/api/evoxc/trace/defn/) | function qualname + module | — | — | — | — | — |
| [`Graph`](/api/evoxc/trace/graph/) | op / function / input / static / output counts, batch marker | counts, specs, static values, digest | pretty-printed IR | — | — | `.evoxcgraph` |
| [`SplitPlan`](/api/evoxc/transforms/splitplan/) | fixed / varying / boundary counts and per-half op counts | the 11 keys | the plan render (leaves, boundary table, digests) | — | — | — |
| [`InputAnalysis`](/api/evoxc/transforms/inputanalysis/) | input / op / output counts plus splittable / blocked | the 5 keys | one row per tensor input | — | — | — |
| [`LoweredProgram`](/api/evoxc/backends/loweredprogram/) | backend, target, payload kind + size, leaf counts | payload and signature summary | raises when the payload has no text form | program text or `None` | — | yes |
| [`CompiledArtifact`](/api/evoxc/backends/compiledartifact/) | backend, target, payload kind + size, leaf counts | payload and signature summary | raises when the payload has no text form | program text or `None` | — | `.evoxcartifact` |
| [`Executable`](/api/evoxc/backends/executable/) | backend, device, input/output leaf counts | specs, trees, required ops, capabilities | — | — | backend plan text or `None` | backend-dependent |
| [`BoundExecutable`](/api/evoxc/pipeline/boundexecutable/) | as `Executable`, plus `bound=N` and reduced inputs | `bound_count` plus the reduced unbound inputs | — | — | delegates | — |
| [`Tensor`](/api/evoxc/core/tensor/) | shape, dtype, device, ≤8-element host preview | — | — | — | — | — |

The `text()` versus `source_text()` split matters: `text()` is the historical accessor that *raises* when a payload has no textual form, while `source_text()` returns `None` in exactly that case. Neither compiles anything.

## `Defn`

**Produced by** `@evoxc.defn`. A [`Defn`](/api/evoxc/trace/defn/) wraps a Python function and marks it as a graph *definition* — it is not a compiled function and not an eager one.

- **Exposed:** `repr` (the wrapped function's qualname and `__module__`), the `__evoxc_defn__` marker, and the wrapped callable.
- **Never does:** trace, compile or run on its own. Calling a `Defn` is what starts a trace, through `evoxc.trace` / `evoxc.build` / `evoxc.evaluate`.
- **Refuses:** calling it with concrete tensors raises [`TraceError`](/api/evoxc/core/traceerror/) directing you to `trace`/`evaluate`.

```python
@evoxc.defn
def f(x, w):
    return evoxc.sum(evoxc.tanh(evoxc.dot(x, w)), axes=1)

f                 # <Defn f …>
f(evoxc.ones((4, 8)), evoxc.ones((8, 4)))   # TraceError, not a result
```

## `Graph`

**Produced by** `evoxc.trace(fn_or_defn, *specs)` or by any graph transform (`vectorize`, `vmap`, `grad`, `jvp`, `vjp`, `batch_functions`).

[`evoxc.split_by_inputs`](/api/evoxc/transforms/split-by-inputs/) is the structural exception among the transforms: it does not hand back a `Graph` itself, but a `SplitPlan` whose `prepare` and `apply` halves are two `Graph`s produced exactly this way.
A [`Graph`](/api/evoxc/trace/graph/) is EvoXIR: a region-based SSA module, the input/output trees, and the static Python values the trace specialized on. Its attributes are `module`, `input_specs`, `output_tree`, `static_values` and `source_locations`.

- **Exposed:** `summary()`, `digest()`, `text()`, `print()`, `verify()`, `save(path)` / `Graph.load(path)`, and the I/O helpers `flatten_inputs(args)`, `unflatten_outputs(flat)`, `validate_inputs(args)`.
- **`digest()`** is a sha256 over the canonical *structural* payload — names, attributes, operand/result SSA ids and types, constants, plus the signature and spec trees — with op source locations and the location-derived payload hash stripped. It is therefore stable across processes, across files, and across `save`/`load`, which is what makes it usable as a cache or comparison key.
- **Never does:** compile, execute, or re-specialize. A transform returns a new `Graph`; the original is untouched.
- **Refuses:** passing anything else to [`evoxc.lower`](/api/evoxc/pipeline/lower/) raises `TypeError` — `lower expects an evoxc.Graph (from evoxc.trace), got …`.

`evoxc.vectorize` requires a traced `Graph`: given a bare function it raises `TypeError` pointing at `evoxc.vmap`, because only `vmap` knows how to trace first.

## `SplitPlan`

**Produced by** `evoxc.split_by_inputs(graph_or_fn, fixed=None, *, fixed_leaves=None)`.

A `SplitPlan` is one traced graph cut into two ordinary graphs plus the boundary between them: the `prepare` half evaluates the fixed inputs once, and the `apply` half runs the varying inputs against the prepared result.

- **Holds:** `source` (the graph that was split), `prepare` and `apply` — ordinary `Graph`s, so each stages through `evoxc.lower` → `evoxc.compile` → `evoxc.load` like any graph, which is why `evoxc.build` is not usable here (it refuses an already-traced `Graph` and points at those three); `fixed_leaves` / `varying_leaves` (flat tensor-input indices into `source.tensor_specs`, ascending); `boundary` (a tuple of [`BoundaryValue`](/api/evoxc/transforms/boundaryvalue/)s in `prepare`'s output order); `unused_varying_leaves` (varying inputs no needed op consumes, kept in `apply` for signature stability); and the properties `boundary_specs` (a `TensorSpec` per boundary value) and `boundary_bytes` (summed static size, `None` when any extent is unknown).
- **Arguments:** `fixed` is a pytree bool / `None` mask mirroring the graph's input structure (`True` keeps a tensor input in `prepare`, `False` / `None` moves it to `apply`; a bare bool broadcasts across all tensor leaves; a non-`None` entry at a static leaf is a `TransformError`), while `fixed_leaves` names the same choice as flat tensor-input indices — the two are alternatives, never combined.
- **Exposed:** `summary()` (11 keys — `fixed_leaves`, `varying_leaves`, `boundary_values`, `boundary_bytes`, `source_ops`, `prepare_ops`, `apply_ops`, `dropped_ops`, `unused_varying_leaves`, `prepare_digest`, `apply_digest` — where the op counts are non-terminator entry-block ops), `as_dict()` (tuples as lists plus a per-value `boundary` list), `text()`, `print()`, `verify()`, and a `repr`.
- **`verify()`** verifies both graphs and the wiring law: `prepare`'s tensor-output count equals `len(boundary)` equals `apply`'s prepared-input count, each position agreeing on shape and dtype (device is compared only when both sides declare one), and `apply`'s tensor-output count equals the source's. A construction bug raises `VerificationError`.
- **Runtime shapes:** `evoxc.run(prepare, *fixed_args)` returns a **flat tuple** of boundary tensors (a fixed dict input keeps its container on the way in — `evoxc.run(prepare, {"w": w, "b": b})` — but the boundary always comes back flat); `evoxc.run(apply, varying_tree, prepared_tuple)` returns the source output tree, because `apply`'s input root is the synthetic two-child tuple `(varying inputs, prepared tuple)` and `run`'s root argument *is* the args tuple.
- **Never does:** mutate the source (its `digest()` is unchanged by a split), execute, trace, or import a backend.
- **Refuses:** giving both or neither of `fixed` / `fixed_leaves` raises `TypeError`; no fixed tensor leaf, or every tensor leaf fixed, raises `TransformError`; a mask that does not mirror the input structure raises `TransformError` naming the first mismatch pytree path; region-bearing control flow (`cond` / `while_loop` / `scan`) and any op whose effect is not `pure` / `read` (collectives, `runtime_call`, `external_call`, `custom_call`, `inline_stablehlo`) raise `TransformError` naming the op and its source location — `block_call` / `rank` / `world_size` are `read` and allowed.
- **`BoundaryValue`** — one tensor crossing the cut: `source_value_id` (the SSA id in the source graph), `spec`, `shape`, `dtype`, `nbytes` (`None` when an extent is unknown), `defining_op` (the op name, `None` for a pass-through input), `location`, `is_input`, the `producer` property (`"<input>"` or the op name), and `summary()` / `as_dict()`.

The boundary is a snapshot of the fixed half's contribution, never re-derived per call: a changed fixed input means re-running `prepare`, and neither graph carries state or invalidation logic.

Given a callable or `Defn` instead of a `Graph`, `evoxc.split_by_inputs` returns a [`SplitCallable`](/api/evoxc/transforms/splitcallable/) whose `sc(*specs)` traces exactly once and returns a `SplitPlan`; concrete `Tensor` arguments raise `TraceError`, because a plan never executes.

## `InputAnalysis`

**Produced by** [`evoxc.analyze_inputs(graph)`](/api/evoxc/transforms/analyze-inputs/); anything that is not a traced `Graph` raises `TypeError`.

It is pure inspection over the same helpers the split uses, so the report cannot drift from the transform — it never mutates, traces, executes or imports a backend.

- **Exposed:** `source`, `inputs` (one [`InputInfo`](/api/evoxc/transforms/inputinfo/) per tensor input in `tensor_specs` order), `op_count` (non-terminator entry-block ops), `output_count` (tensor output leaves), `splittable`, `blocked_reason` (the split gate's message verbatim, `None` when splittable), `split(fixed=None, *, fixed_leaves=None)` (sugar over `evoxc.split_by_inputs(self.source, …)` — a blocked graph re-raises exactly the gate's `TransformError`), `summary()` (5 keys — `input_count`, `output_count`, `op_count`, `splittable`, `blocked_reason`), `as_dict()`, `text()`, `print()`, and a `repr`.
- **`InputInfo`** — one tensor input's facts: `index` (the tensor-input index that `fixed_leaves` uses), `path` (the pytree path, e.g. `[1]` or `[0]['w']`), `spec`, `nbytes`, `direct_consumers`, `op_count` (ops transitively depending on it), `outputs` (indices of the tensor output leaves it influences), `boundary_bytes` / `boundary_count` (what fixing that input alone would cost — `None` when the graph is not splittable or fixing it alone is not a legal split; a legal split that crosses nothing reports `0` / `0`), plus `summary()` / `as_dict()` / `repr`.
- **Axis note:** `index` is the tensor-input axis `fixed_leaves` uses, while `path` is rendered over tree-leaf positions (which also count static leaves), so the two are not interchangeable.

A graph blocked by control-flow regions or effectful ops still reports full per-input facts — that gate blocks the split, not the counting — and only the `boundary_bytes` / `boundary_count` fields become `None`. A defensive module-shape gate (a module that is not exactly one function, a multi-block region, a missing `return` terminator) has no single entry block to walk, so it reports `splittable=False` with zeroed facts instead: `op_count` is `0` and each `InputInfo`'s `direct_consumers` / `op_count` / `outputs` are `0` / empty.

## `LoweredProgram`

**Produced by** [`evoxc.lower(graph, backend=None, **options)`](/api/evoxc/pipeline/lower/). The backend verifies the graph, records its signature (input/output tree, specs, static values) and produces its own payload — StableHLO MLIR text for a compiler backend, a serialized program for the numpy interpreter, a serialized EvoXIR module for `native`.

- **Exposed:** `backend`, `signature`, `summary()`, `source_text()`, `text()`, `save(path)` / `LoweredProgram.load(path)`.
- **Never does:** compile. `save`/`load` are the persistence round trip and nothing else.
- **Refuses:** [`evoxc.compile`](/api/evoxc/pipeline/compile/) of a non-`LoweredProgram` raises `TypeError`; compiling a program produced by one backend with another backend raises [`BackendError`](/api/evoxc/core/backenderror/) — never a silent re-lower.

## `CompiledArtifact`

**Produced by** [`evoxc.compile(lowered, backend=None, **options)`](/api/evoxc/pipeline/compile/) — or by [`evoxc.compile_text`](/api/evoxc/pipeline/compile-text/), which builds the lowered program itself from text you supply.

- **Exposed:** `backend`, `signature`, `target`, `summary()`, `source_text()`, `save(path)` / `CompiledArtifact.load(path)`.
- **Never does:** load onto a device; that is `load`'s job. It carries no live device handle, which is why it is the object you persist.
- **Refuses:** `evoxc.load(artifact, backend=...)` with a backend that differs from the producing one raises [`PersistenceError`](/api/evoxc/core/persistenceerror/) — never a silent recompile. Passing a non-`CompiledArtifact` to `load` raises `TypeError`.

## `Executable`

**Produced by** [`evoxc.load(artifact, backend=None, device=None, **options)`](/api/evoxc/pipeline/load/), or directly by [`evoxc.build`](/api/evoxc/pipeline/build/), [`evoxc.build_cached`](/api/evoxc/build-cache/build-cached/) or [`evoxc.compile_text`](/api/evoxc/pipeline/compile-text/).

An [`Executable`](/api/evoxc/backends/executable/) is a device-bound wrapper: the backend executable plus the decoded signature used to validate every call.

- **Exposed:** `functions`, `device`, `backend`, `summary()`, `plan_text()`, `synchronize()`, `save(path)` / `Executable.load(path, backend=None, device=None)`.
- **`plan_text()`** delegates to the backend's textual plan (the numpy interpreter's per-block plan, the `native` engine's plan render) or returns `None` when the backend has none.
- **Never does:** re-trace, re-compile, or move a tensor between devices.
- **Refuses:** [`evoxc.run(exe, …)`](/api/evoxc/pipeline/run/) with a structurally wrong input tree, a wrong dtype/shape or a tensor on the wrong device raises [`TraceError`](/api/evoxc/core/traceerror/) / [`DTypeError`](/api/evoxc/core/dtypeerror/) / [`ShapeError`](/api/evoxc/core/shapeerror/) / [`DeviceError`](/api/evoxc/core/deviceerror/) before backend dispatch; `bind` accepts only a plain `Executable` and raises `TypeError` on a `BoundExecutable`; `save` raises `PersistenceError` when the backend executable cannot serialize itself, directing you to `artifact.save(path)` plus `evoxc.load`.

### `Executable.synchronize()`

Device-resident execution may enqueue instead of blocking, so a wall-clock measurement needs an explicit join.

- Output `Tensor`s' **values** are valid before the call — any read awaits.
- `synchronize()` waits for device work submitted by earlier `run()` calls; it exists for **timing** and for reusing buffers, not for correctness of reads.
- Nothing calls it implicitly, and `evoxc.run` performs no per-call sync — dispatch overlap stays a feature.
- Backends whose `run()` already blocks (numpy, iree) document it as a no-op; a backend with an asynchronous `run` (xla) awaits and destroys the pending events.
- `BoundExecutable.synchronize()` delegates, so a bound executable exposes the same call shape.

## `BoundExecutable`

**Produced by** [`evoxc.bind(executable, **bindings)`](/api/evoxc/pipeline/bind/). Pure argument-supply sugar: names, dtypes, shapes and devices are validated, and the graph is never altered or recompiled.

- **Exposed:** `summary()` (the wrapped summary plus `bound_count`, with `input_count`/`input_specs` reduced to the inputs a caller still supplies), `plan_text()` and `synchronize()` delegating to the wrapped executable, `functions`, `device`.
- **Never does:** change the graph, re-compile, or transfer a bound tensor. A binding on another device fails fast with the run-boundary `DeviceError`.
- **Refuses:** binding a name the graph does not declare raises `TraceError` listing the available names; binding a `BoundExecutable` raises `TypeError` (call `evoxc.bind` once, on the executable).

```python
spec = evoxc.TensorSpec((8, 4), evoxc.float32, name="w")
graph = evoxc.trace(f, evoxc.TensorSpec((4, 8), evoxc.float32), spec)
exe = evoxc.load(evoxc.compile(evoxc.lower(graph)))
bound = evoxc.bind(exe, w=w)
evoxc.run(bound, x)      # `w` is supplied; `x` is still an argument
```

## `Tensor`

**Produced by** [`evoxc.run`](/api/evoxc/pipeline/run/) and by the concrete creators ([`evoxc.tensor`](/api/evoxc/core/tensor/), [`evoxc.zeros`](/api/evoxc/core/zeros/), [`evoxc.from_numpy`](/api/evoxc/core/from-numpy/), …). A [`Tensor`](/api/evoxc/core/tensor/) is a materialized runtime tensor whose `device` is always physically true.

- **Exposed:** `shape`, `dtype`, `device`, `.numpy()`, `.to(device)`, `__dlpack__` / `__dlpack_device__`, and a `repr`.
- **`repr`** shows shape, dtype and device plus a compact value preview **only** for an ndarray-backed tensor of at most 8 bool/integer/float/complex elements, and the payload class name for a device payload. It never calls `.numpy()`, never materializes a host copy, never forces a transfer and never raises.
- **Never does:** exist inside a graph. In a trace, values are [`SymbolicTensor`](/api/evoxc/core/symbolictensor/)s, which have no `.numpy()`, no `__dlpack__` and no data pointer at all.
- **Refuses:** `.numpy()` on a non-cpu payload raises [`DeviceError`](/api/evoxc/core/deviceerror/) (use `.to(evoxc.Device("cpu", 0)).numpy()`); `evoxc.run` rejects a tensor leaf whose device differs from the executable's with a `DeviceError` naming the pytree path and both devices.

`Tensor.to(device)` is the only transfer primitive in the library: equal device returns `self`, `to(cpu)` is the explicit device-to-host readback, and `to(non-cpu)` resolves the owning backend's transfer provider (a missing provider is a [`DeviceError`](/api/evoxc/core/deviceerror/)).

## Stage mismatches, in one table

| Call | Wrong argument | What happens |
|---|---|---|
| `evoxc.lower` | anything but a `Graph` | `TypeError` naming `evoxc.Graph` and `evoxc.trace` |
| `evoxc.analyze_inputs` | anything but a `Graph` | `TypeError` naming `evoxc.Graph` and `evoxc.trace` |
| `evoxc.split_by_inputs` | both or neither of `fixed` / `fixed_leaves` | `TypeError`; all-fixed or no-fixed is a `TransformError` |
| `evoxc.compile` | anything but a `LoweredProgram` | `TypeError` naming `evoxc.backends.LoweredProgram` |
| `evoxc.compile` | a program from a different backend | `BackendError` — never silently re-lower |
| `evoxc.load` | anything but a `CompiledArtifact` | `TypeError` naming `evoxc.backends.CompiledArtifact` |
| `evoxc.load` | an artifact from a different backend | `PersistenceError` — never silently recompile |
| `evoxc.run` | anything but `Executable` / `BoundExecutable` | `TypeError` naming both |
| `evoxc.bind` | a `BoundExecutable` or a non-executable | `TypeError` directing you to bind the executable |
| a `Defn` | called with concrete tensors | `TraceError` directing to `trace`/`evaluate` |
| an op function | called with a concrete `Tensor`, or outside a trace | `TraceError` (no eager mode) |
