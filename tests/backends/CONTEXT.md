# tests/backends — backend-layer test suite
## Intent
pytest suites validating `evoxc.backends` (sibling: `../../evoxc/backends` — read its CONTEXT.md and `../../evoxc/CONTEXT.md` before changing expectations): the backend interface/registry/program contracts, the numpy interpreter backend (the numerical reference), the StableHLO exporter, and the iree / xla / tvm adapters.
Tests are the executable spec of the backend contract: graphs executed by the numpy backend must match direct numpy references computed with the SAME formulas as the kernels in `evoxc/backends/numpy/kernels/`.

## Conventions (binding for this directory)
- Run from repo root: `python3 -m pytest -q tests/backends` (the root `conftest.py` handles sys.path). Pure-lower/golden files are numpy-only, CPU-only, small shapes, <2 s; the adapter/parity/plugin files run REAL compilers or a gcc build (`test_adapter_{iree,xla,tvm}.py`, `test_iree_*parity*`, `test_iree_eigh_diag_parity.py` with n up to 100, `test_external_*iree.py`, `test_build_cache_iree.py`, `test_pjrt_*`/`test_xla_*`), so the <2 s rule does not apply there — keep compile counts low and reuse one compiled executable per graph.
- **Inventory (measured here with `iree-base` 3.13.0 installed, the AMD MI300X present — so the ROCm/HIP legs RUN — a usable Vulkan device present (Mesa lavapipe, `VK_ICD_FILENAMES` UNSET) — so the device-guarded Vulkan suite RUNS — and NO NVIDIA GPU, NO PJRT plugin, NO tvm and NO torch):** 1510 tests collected across 46 contributing files — 1456 passed, 54 skipped, 3 xfailed, 0 failed, ~109 s (dominated by iree compiles); the summary line reads 57 skipped because 3 of the directory's 49 test modules collection-skip at import when their optional adapter is absent (`test_adapter_tvm.py`, `test_adapter_xla.py`, `test_external_portable_fallback.py`), so reported items = 1513. The 51 contributing skips are 27 cuda guards (22 `nvidia-smi`-guarded + the 5 cuda-HAL `Device("cuda", 5)` smokes in `test_iree_emitters_parity.py`), 13 tvm-absent (12 `could not import 'tvm'` — 6 `test_mixed_dtype.py`, 3 `test_opt_level.py`, 3 `test_options_override.py` — plus the 1 adapter-level tvm parametrization of `test_external_call_iree.py`), 8 PJRT-plugin-absent xla items (6 `test_mixed_dtype.py`, 2 `test_nsga2_xla_route.py`) and 3 torch-absent ROCm DLPack items (`test_iree_device_dlpack.py`) — there is NO Vulkan skip here. In the uv environment iree's nanobind atexit noise can swallow the summary line — read it via `--junit-xml`.
- **Compiler-free runs (no `iree`/`tvm`/torch/PJRT plugin):** every REAL-compiler leg skips through its per-test `pytest.importorskip`, while the helper-level fake-adapter legs must still PASS — a fake that only installs the submodule (no parent package) silently turns into a `ModuleNotFoundError` failure there. Measured: `test_options_override.py` = 83 passed / 11 skipped / 3 xfailed in a compiler-free env, 91/3/3 with `iree` present (tvm absent), 97 collected either way; the five-file xla command (`test_xla_plugin_discovery.py` + `test_pjrt_ctypes_plugin.py` + `test_xla_device_resident.py` + `test_options_override.py` + `test_adapters_optional.py`) = 154 passed / 12 skipped / 3 xfailed in a numpy-only venv with gcc and no plugin (the same counts in a venv that DOES carry a real `jax_plugins` plugin — the discovery suite is ambient-box isolated).
- Execute graphs via `evoxc.evaluate(fn, *args, backend=evoxc.backends.numpy_backend)` or `evoxc.build`+`evoxc.run`; results are `evoxc.Tensor` — unwrap with `.numpy()`.
- Numerical references re-implement the kernel formulas (never import evoxc kernels): `math.erf` for erf, `0.5*x*(1+erf(x/sqrt(2)))` for gelu, manual dilate→pad→cross-correlate loops for conv. Exact equality for int/bool; float32 rtol=atol=1e-6, float64 rtol=atol=1e-12; result dtype asserted.
- Documented evoxc quirks encoded as tests (do NOT "fix" evoxc here): `evoxc.slice` lengths are spans (limit = start+length, numpy `x[s:s+l:st]`); `solve` needs rhs `(..., n, k)` for batched `a`; getitem supports only static int/slice; `dot` requires rank ≥ 2; `evoxc.scan` desugars to while+gather+scatter at trace time (its stablehlo export error names `gather`).
- Shared state hygiene: the collective-executor hook and rank context are process/thread global — tests touching them use fixtures to save/restore.
- **Explicit device placement (binding).** A run input must ALREADY live on the executable's device: place it with `Tensor.to(device)` BEFORE `evoxc.run` — host ndarrays and cpu:0 tensors are rejected at the run boundary with `core.DeviceError` naming the input path (no implicit host→device transfer there) — and materialize outputs through the explicit `out.to(Device('cpu', 0)).numpy()` hop, since `.numpy()` on a non-cpu-kind payload raises `core.DeviceError`. llvm-cpu executables keep the UNCHANGED host-input path (raw ndarray / cpu:0 `core.Tensor` inputs via `asdevicearray`) with lazy per-call `.numpy()` on cpu-kind payloads.
- **ROCm/HIP placement** is the same model on the AMD target: gate GPU legs with `_rocm_guard.require_rocm()` (returns the evoxc `Device("rocm", 0)`), compile with `target_backends=["rocm"]` and run with `device=Device("rocm", idx)` (the iree `hip` driver's `device_id = idx + 1`; `"hip"` is the accepted evoxc alias, label preserved, so place inputs with `Tensor.to(Device("hip", idx))` for a `"hip"`-labelled executable). Mind the stage asymmetry `evoxc.build` hides: `target_backends` is a COMPILE-stage option (accepted-and-ignored at lower/load), so the explicit pipeline is `lower(graph, backend="iree", target_backends=["rocm"])` → `compile(lowered, target_backends=["rocm"])` → `load(artifact, backend="iree", device=rocm)`. ROCm uploads take the generic `iree.runtime.asdevicearray` path (no cuda-only persistent-staging tiers).
- **No `nvidia-smi` on the ROCm path** — never port the cuda suites' most-free-GPU scan to ROCm; use `_rocm_guard`'s `hip` capability probe. Keep GPU legs to short correctness checks (no timing) since the box may be shared.
- **xla plugin resolution is ambient (binding for every xla test).** `xla_util._find_plugin_path` resolves `plugin_path` → `EVOXC_PJRT_PLUGIN` → the fixed well-known paths → an installed `jax_plugins/*/*.so` scan, so "a plugin is configured" no longer implies a CPU plugin: `pip install jax-rocm7-pjrt` (or `jax-cuda12-pjrt`) makes a GPU plugin resolvable on an accelerator box — registration never probes for it (`xla.register()` is unconditional), so the plugin is a per-call artifact and the adapter REFUSES the CPU/`device=None` load path for a platform that cannot serve `cpu` (`_check_kind_served`). Consequences: (a) any test that must observe "no plugin anywhere" has to neutralize ALL four steps — delete both env vars, empty `xla_util._DEFAULT_PLUGIN_PATHS`, set `EVOXC_PJRT_PLUGIN_DISCOVERY=0` (or reset the scan cache) — and never assume the box is bare; (b) a real-plugin suite must derive its run device from the plugin's platform through `_xla_plugin_probe` rather than hard-coding CPU, and use the explicit placement/readback helpers on an accelerator; (c) tests that pin resolution itself REPLACE `sys.path` (candidates sort by path string, not by sys.path position) and reset `xla_util._reset_plugin_discovery_cache()` before and after — successful `CDLL` handles stay alive in `_plugin_handles` for the process and are never unloaded.
- **Env-gating convention for adapter-fake tests (binding).** Where a test pins an adapter helper that internally does `import <dep>...` without needing a real compiler, the fake must be COMPLETE — install a fake top-level PACKAGE module (`types.ModuleType("<dep>")` with `__path__ = []`) in `sys.modules` as well as the submodule, otherwise the in-function `import <dep>.<sub>` raises `ModuleNotFoundError` before the submodule entry is consulted (a compiler-free environment must still RUN the test — never `importorskip` it). When the REAL package is already imported, patch its existing attribute (e.g. `runtime`) instead of clobbering the real module. Every install goes through `monkeypatch.setitem`/`setattr` so the sys.modules entries and attributes are restored on teardown; nothing leaks between tests. Reference implementation: `test_options_override.py::_install_fake_iree_runtime` (fake `iree` + `iree.runtime` + `iree.runtime.flags`).
- **Adapter test conventions** (`test_adapter_{iree,xla,tvm}.py` + `_adapter_utils.py`): each pins the SHARED `evoxc/backends/compiler.py` CompilerBackend contract and its adapter, is guarded by module-level `pytest.importorskip(<dep>)` calls BEFORE the evoxc imports (xla instead module-skips through `_xla_plugin_probe.require_plugin()` — registration is unconditional, so the module-level skip is the probe's no-plugin `core.BackendError` — then derives its run device from the plugin's platform), uses `NAME = "iree"/"xla"/"tvm"`, and shares every graph/input/tolerance via `_adapter_utils` (import as `from tests.backends import _adapter_utils as u`). fp32 parity tolerance is 1e-5 (cross-compiler), not 1e-6.
- **BUG(evoxc) policy:** when a test exposes a real evoxc bug, keep the assertions intact and report it upward with a minimal repro. Never fix evoxc and never weaken the test. Two equivalent mechanisms: a plain failing test with a `# BUG(evoxc): <description>` comment, or — where the node must stay green for sibling suites — `@pytest.mark.xfail(strict=True, reason="BUG(evoxc): …")` with the same comment above it (the assertions still exercise the CORRECT result and the pin XPASSes — failing loudly — the day evoxc is fixed, which is the signal to delete the marker). One pin remains in this node (see Known Issues).
- **Exporter-option goldens (eigh / split reduction):** pin markers from the ACTUAL emitted text and mind the quoting form — `stablehlo.remainder` is emitted bare/functional (count the UNQUOTED substring), while generic ops (`"stablehlo.while"`, `"stablehlo.reduce"`, `"stablehlo.transpose"`, `"stablehlo.if"`, `"stablehlo.slice"`) use the quoted custom-op form. Option VALUES are validated by the Writer (loud `BackendError` naming the accepted set), option KEYS by `options.validate_options`.
## Known Issues
- v1 collective-protocol limitations (asserted as-is): `reduce_scatter`'s `reduce_op` is not forwarded to the executor; `all_to_all` forwards only `split_axis`; `dist.broadcast` records the default `src_rank=0` in IR even when the user passes another value.
- **`split_reduction_threshold` / `split_reduction_non_exact` are exporter-only** (plumbing gap): the StableHLO Writer normalizes and honours them, but no adapter declares them in `KNOWN_OPTIONS["lower"]` and `CompilerBackend._exporter_options` does not forward them, so they are unreachable through `lower()`/`build()` (loud unknown-option `BackendError`). Consequence: `test_split_reduction.py` drives them by calling `stablehlo.export(graph, options=...)` directly, `test_iree_split_reduction_parity.py` goes through the real adapter via a file-local `_compile_with_exporter_options` helper (export with options → swap `mlir_text` into a `LoweredProgram` → compile/load), and `test_options_override.py::test_split_reduction_sub_options_forwarded_through_lower` pins the DESIRED public plumbing as a strict xfail (3 parametrized cases = the node's 3 xfails). Only the plain `split_reduction` and `eigh_algorithm` keys are plumbed.
- **`eigh_algorithm` / `split_reduction` env rows live outside this node:** `evoxc.pipeline_options.ENV_OPTION_TABLE` holds three `(backend, "lower")` rows (`iree`/`xla`/`tvm`), each with `EVOXC_EIGH_ALGORITHM` → `eigh_algorithm` (value validated by the Writer: `jacobi` | `jacobi_batched`) and `EVOXC_SPLIT_REDUCTION` → `split_reduction` (`normalize_bool_option`), applied by `pipeline.lower` with explicit-kwarg > env > adapter-default precedence; their env-half tests are in the sibling `tests/test_pipeline_options.py`. This node covers only the explicit-kwarg/exporter plumbing, and the two sub-knobs above have NO env row.
- **The Vulkan device-guarded suite needs a Vulkan device IREE ENUMERATES:** `test_iree_vulkan_device_resident.py` runs only where the `vulkan` HAL driver enumerates a device. On the adopted `iree-base` 3.13.0 this host's Mesa lavapipe is enumerated with `VK_ICD_FILENAMES` UNSET (the 3.11 device-name denylist in `iree_hal_vulkan_is_device_visible()` no longer hides `llvmpipe`), so the suite RUNS — 6/6 green — on the only Vulkan device this box has: the AMD MI300X has no GPU-Vulkan path (RADV policy-rejects CDNA3, AMDVLK has no CDNA IP path, the amdgpu DRM device is wedged), so every vulkan result here is software-device correctness, never a GPU performance number. Where nothing is enumerated, point `VK_ICD_FILENAMES` at a RENAMED lavapipe ICD (3.11-era fallback; recipe in `.agents/skills/evoxc-vulkan-device-recipe.md`). Host materialization on the Vulkan HAL is adapter-owned: 3.13's `DeviceArray.to_host()` fast path fails there (the runtime prefers `allocator.import_host_allocation` and the Vulkan allocator rejects the buffer it advertised), so `.numpy()` / `.to(cpu)` go through the adapter's explicit staged copy.
- **Same-thread finalizer deadlock in `xla_util.acquire_client` — FIXED + PINNED:** `acquire_client` used to hold the non-reentrant `_shared_clients_lock` across `plugin.create_client()`, so a payload/client finalizer firing during that call re-entered `release_payloads` (which takes the same lock) on the SAME thread and hung the process forever (observed as a full `pytest tests/backends` run stopping inside `test_xla_device_resident.py::test_load_device_validation`). Fixed in `evoxc/backends/adapters/xla_util.py`: client creation happens OUTSIDE the shared-clients state lock, serialized by the dedicated `_client_create_lock`; `_shared_clients_lock` is now an `RLock` (second line of defence); every finalizer takes the state lock only for the refcount bookkeeping and runs all plugin calls (`buffer.close()`/`client.close()`) outside it. Pinned by `test_xla_device_resident.py::test_acquire_client_finalizer_inside_create_does_not_deadlock` (§5b) — a SUBPROCESS test whose stub plugin runs `gc.collect()` inside `create_client()` with a deterministically-pending finalizer (cyclic referent + `gc.disable()`), asserting the state lock is NOT held and `_client_create_lock` IS held at that point, so a regression fails fast on the assertion or on the subprocess timeout instead of hanging the test process. `TestIreeBindingLimitError::test_real_rocm_driver_binding_wall` no longer needs its `del`/`gc.collect()` workaround.
