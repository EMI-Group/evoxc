# tests — evoxc test suite

## Intent

pytest suite validating the `evoxc` package (sibling — see `../evoxc/CONTEXT.md` for the API contract being tested). Tests are the executable spec of design principles: explicitness, no hidden magic, local-tensor semantics, sugar transparency.
Per-pin detail lives in the AREA CONTEXT files (`./backends/CONTEXT.md`, `./ops/CONTEXT.md`, `./io/CONTEXT.md`, `./sparse/CONTEXT.md`, `./formats/CONTEXT.md`, `./native/CONTEXT.md`) — those are the authority; this file keeps the layout, the cross-cutting conventions and the recorded baseline.

## Structure

Mirror the package: `tests/core/`, `tests/ir/`, `tests/ops/`, `tests/numpy/`, `tests/trace/`, `tests/block/`, `tests/transforms/`, `tests/backends/`, `tests/dist/`, `tests/persist/`, `tests/formats/`, `tests/native/`, `tests/io/`, plus root-level modules:

- `pipeline_test.py` (28) — end-to-end staging pipeline (trace→lower→compile→load→run), `bind`, `build`, `evaluate`; the explicit `Executable.synchronize` surface (callable / `None` / idempotent / value-neutral, backend forwarding, documented no-op, `BoundExecutable` delegation, and the pin that `run`/`evaluate` never synchronize implicitly); run/bind **boundary device enforcement** (every input must already live on the executable's device — a cuda-kind tensor with a fake payload fed to the cpu executable raises `DeviceError` naming the input pytree path, with the `t.to(...)` remedy; raw host ndarrays auto-wrap as cpu:0; the explicit `t.to(cpu)` unblocks the foreign tensor).
- `pipeline_env_defaults_test.py` (61) — `EVOXC_BACKEND`/`EVOXC_DEVICE`/`EVOXC_TARGET_BACKENDS` for `build`/`evaluate`: explicit kwargs win, env read lazily per call, the `vulkan` kind parse (`"vulkan"`/`"vulkan:N"`), `_resolve_backend_device` inferring `["vulkan-spirv"]` for iree-family backends only; stub-backed full-path tests (never a real adapter).
- `test_pipeline_options.py` (80) — the env half of the option plumbing (`pipeline_options.apply_env_options`/`ENV_OPTION_TABLE`): per-stage application, explicit > env > default, empty = unset, malformed → `BackendError` naming var+value, the `EVOXC_OPT_LEVEL` / `EVOXC_IREE_VULKAN_TARGET` / `lower`-stage `EVOXC_EIGH_ALGORITHM` + `EVOXC_SPLIT_REDUCTION` entries (a real `bool`, never the `bool("0")` trap) with the autouse `_clean_option_env` fixture, the iree custom-build seam rows `EVOXC_IREE_COMPILER_MODULE` → `iree_compiler_module` (compile) and `EVOXC_IREE_RUNTIME_MODULE` → `iree_runtime_module` (load) — dotted module paths, whitespace-stripped only — plus two gated end-of-file pins through the real iree adapter. The backend half is `backends/test_options_override.py` (97) + `backends/test_opt_level.py` (53).
- `test_pipeline_backend_instance.py` (8) — a passed `Backend` INSTANCE reaches every hop: `build`/`build_cached` resolve it ONCE and call THAT instance at lower, compile AND load (a recording decoy backend is registered under the same name, so the pin is not trivially true by name resolution), the same options dict is forwarded to all three hops, the trace body runs before the first backend hop (documented expansion order), `build_cached` returns the identical executable on a hit with zero pipeline work, and `load(artifact, backend=<instance>)` uses the instance (not a name lookup) while keeping the existing `PersistenceError` on an instance/name mismatch.
- `test_compile_text.py` (11, iree-guarded) — `evoxc.compile_text`: hand-written StableHLO text compiled through iree (dynamic `tensor<?x4xf32>` reused across two batch sizes, two inputs → a TWO-output FLAT tuple result, `entry_functions`/`device` handling, `target_backends` forwarding plus an invalid-target adapter `BackendError`), the validation error paths (non-str/empty/whitespace text, non-`TensorSpec`/non-sequence specs, empty `output_specs`, bad `entry_functions`, `backend="numpy"`/`"native"` → the explicit `BackendError` naming the backend), and an `stablehlo.export` → `compile_text` round trip compared against the original executable.
- `test_build_cache.py` (31) — `build_cached`/`CompileCache`: the key computed BEFORE tracing (fn identity as keepalive, full specs tree incl. static content, resolved backend/device, canonicalized options), key sensitivity, env-default resolution (malformed values count NO miss), LRU/`clear()`/counters, error propagation (trace failures never cache, unencodable static leaves → pre-cache `TypeError`), zero pipeline work on hits, thread-safety, static args stay in the run signature.
- `test_meta_programming.py` (5) — a miniature GP harness: random expression programs encoded as tensors, prefix-decoded into static trees, one `build_cached` per distinct tree, executables reused across the inner evaluation loop, every executable vs a pure-numpy tree evaluator.
- `test_packaging.py` (53) — the two-distribution contract (`evoxc` root mixed-maturin project + `evoxc-hf` workspace member): reads both `pyproject.toml`s with `tomllib`, walks the checkout, inspects installed metadata and builds REAL artifacts from a throwaway copy (`uv build --all-packages`; no toolchain → `pytest.skip`; the cap and env are self-contained — see below).
That build is self-contained: `_run_build` (the ONE helper both the session-wide workspace build and the standalone planted-`egg-info` build go through) runs each `uv build` in `os.environ` PLUS the fast-but-still-release Cargo knobs `CARGO_PROFILE_RELEASE_LTO=false` / `CARGO_PROFILE_RELEASE_CODEGEN_UNITS=16`, applied only when the caller left them unset, so a cold extension build cannot outlive the test.
The build cap is 1800 s per command, overridable with `EVOXC_TEST_BUILD_TIMEOUT=<seconds>`; expiry FAILS with that knob named in the message (never a skip), while a missing toolchain or a failing build keeps the existing skip-with-reason path.
The knobs change compile time only — the artifacts stay release, abi3, stripped wheels carrying the loadable `evoxc/_evoxc_native.abi3.so`, which the existing assertions still pin.
Pins the workspace wiring (`[tool.uv.workspace].members`, `uv.lock`, `[tool.uv.sources]`, maturin backend + `[tool.maturin]` fields, the member on `uv_build`), identity/metadata (names vs import names, per-project PEP 440 versions, numpy-only deps, `evoxc` extras `{interop, dev, iree, tvm, compilers, bench}` with `hf` ABSENT, member extras `{hf, dev}`), the sdist-only `[tool.maturin] include`, the layout boundary (no `evoxc_hf/__init__.py`, LICENSE symlink, README), source purity (`import evoxc` pulls neither `evoxc_hf` nor torch/transformers), each wheel/sdist root set exactly its own module + dist-info, plus an OPTIONAL `<dist>.libs/` directory of bundled shared libraries on the compiled `evoxc` wheel only (maturin's musllinux repair; every entry a single directly-nested `.so`/`.so.<digits>`/`.dylib`/`.dll` file, never a Python module, and never on the pure-Python `evoxc_hf` wheel), the stale-`egg-info`-manifest trap, and release hygiene (version single-sourcing, PEP 639 in both projects and wheels, `CHANGELOG.md` heading + link).
- `test_inspection.py` (66) — `Graph.__repr__`/`summary()`/`digest()` (stable in-process, across processes, files and `save`→`load`; a changed attribute changes it)/`text()`, `LoweredProgram`/`CompiledArtifact` reprs + save/load, `Executable.__repr__`/`summary()`/`plan_text()` (numpy + native, guarded), `BoundExecutable`, `Defn.__repr__`, `Tensor.__repr__` never materializing a device payload.
- `test_spec_compliance.py` (89) — design-principle compliance: no implicit tracing/eager mode; closure-captured tensors → `TraceError` while `evoxc.constant` is the explicit opt-in; `SymbolicTensor` has no `.numpy()`/`__dlpack__` and `bool(symbolic)` fails; `build`/`evaluate` = documented shorthand with distinct stage types; `bind` never alters the graph/compile; `vmap` ≡ `vectorize`; concrete creators vs `enp` graph ops; serialization round-trips; Python values → Python semantics; collectives are explicit IR ops; `TestExplicitPlacement` (group 15, 7) and `TestSparseExplicitness` (group 14, 21); error messages carry source locations.

Other suites: `formats/` 195 (`evoxc.formats` safetensors 75 + GGUF 115 + surface 5 over synthetic files, per-pin detail in its own CONTEXT.md); native-backend suites (`backends/_native_utils.py` + `test_native_backend{,_missing_engine,_parity_core,_parity_structure,_parity_random,_features,_perf_shape}.py` = 32/10/155/122/70/33/5 + `test_numpy_single_decode.py` 15 — 442 items, extension OPTIONAL); external-kernel suites (`ops/test_external_call.py` 42, `ops/test_external_rules.py`, `ops/test_external_batched.py` 20, `backends/test_external_call_iree.py` 39, `backends/test_external_batched_iree.py` 5, `backends/test_external_portable_fallback.py` tvm-gated, `backends/test_iree_device_dlpack.py`, `block/test_portable_vjp_regression.py`); `io/` 74 (`test_io.py` 37 + `test_io_worker_bootstrap.py` 37) with the iree parity legs in `backends/test_iree_host_io_parity.py` 11.

## Constraints

- CPU only; the numpy backend is the reference for correctness.
- torch-dependent tests use `pytest.importorskip("torch")` (interop is optional).
- No GPU usage. No network. Keep tests fast (<2 s per file, no large shapes beyond ~256×256 unless needed).
- **Timing pins are regime-change detectors, never micro-benchmarks:** on a shared host a wall-clock assert must carry ≥50× headroom over the recorded median AND be paired with a behavioural (bit-exactness / plan-shape) assertion — `backends/test_native_backend_perf_shape.py` is the pattern.

Compiler adapters inline portable `block` decompositions through the shared `inline_portables` path — no `block_call` survives into the exported StableHLO, while a backend-only block is rejected at the capability pre-check with a `BackendError` naming the block: `backends/test_block_portable_compiler.py` (7, pinned through the numpy interpreter, a `CompilerBackend` stub and iree).
Registry extensibility is `backends/test_registry_extensibility.py` (11 — `register(..., replace=True)` swaps an instance while a duplicate name still raises `BackendError`, `unregister(name)` returns the instance or raises for an unknown name, and the `evoxc.backends` entry-point group is scanned once per process on a `get()` miss across module/`register()`, callable and `Backend`-instance shapes, with a failing entry point chained as `BackendError.__cause__`).
The iree custom-build seam is `backends/test_iree_module_option.py` (7 — `iree_compiler_module` resolved at compile and `iree_runtime_module` at load, module object or dotted path, with a bogus path raising a `BackendError` naming option and value), complementing the `EVOXC_IREE_{COMPILER,RUNTIME}_MODULE` env rows in `test_pipeline_options.py`.

`batch_functions` hooks: `transforms/test_batch_functions_speed_pins.py` (a merge calls `ops._utils.get_location` zero times with a positive control, never `inspect.stack`, measured op/class/switch/mux pins read from `graph.batch_report`, locations preserved) and `test_batch_functions_bands.py::test_auto_bands_a_divergent_gp_population` (the geometric ladder on a divergent 16-program population).

**Rank-0 random sampling (`backends/test_numpy_random_scalar_shapes.py`, 83)** — the numpy interpreter's "Scalar-shape contract": `random_uniform`/`random_normal` (both branches)/`random_randint` COMPUTE their result, so a `shape=()` draw normalizes with `np.asarray` and returns a 0-d `core.Tensor` on cpu:0 whose `.numpy()` is a genuine 0-d ndarray; parametrized over the three algorithms × f16/f32/f64 uniform + normal(`mean=1.0, std=2.0`) + int32 `randint(low=-7, high=13)` + int64 `randint(high=2**40)` — dtype/shape/device, scalar == `(1,)`[0] from the same key, determinism, numpy-vs-native exact (`np.array_equal`; the f32 `normal` ⊕`philox4x32_10` leg uses the documented `rtol=1e-6` fast-path budget), plus `permutation(n=0)`/`(n=1)` as real `(0,)`/`[0]` int32 arrays, exact vs native.

**Native fast-path shape pins (`backends/test_native_backend_perf_shape.py`, 5)** — the CPU engine's strided-run slice / broadcast-add / typed-random paths, pinned by SHAPE not throughput: a `(500,50,4)→(500,50,1)` slice + broadcast add + `random.uniform(500×17)` graph matches the numpy backend (and at a second static size 37×5×3), the compiled plan is one flat block carrying the static `(dtype, shape)` markers (`static float32[500, 50, 1]`, `static float32[500, 17]`), the warm `run` median stays under a 5 ms ceiling (recorded median ~0.054 ms → ~90× headroom; a lost fast path costs 10–100×), and `native/tools/bench_cpu.py` still defines the original eight workloads incl. `tn_step_pop500` (the harness now carries seventeen, including the 16M-element large-op rows).
